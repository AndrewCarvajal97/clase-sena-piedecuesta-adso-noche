La gran idea

🔢

Un modelo de IA no entiende letras ni palabras.
Solo entiende números.

Todo lo que veremos hoy es, en el fondo, cómo se traduce el lenguaje a números y de vuelta.

Tokenización · Paso 1: partir el texto

Un token es un pedacito de texto: una palabra, parte de una palabra o un signo.

Texto:   "Aprender IA es genial"
Tokens:  ["Apr", "ender", " IA", " es", " genial"]
         (ejemplo ilustrativo)
Regla prácticaEn promedio 1 token ≈ 4 caracteres ≈ ¾ de palabra en inglés. En español suele ocupar un poco más.

Tokenización · Paso 2: cada token es un número

El modelo tiene un vocabulario (una tabla) donde cada token tiene un ID:

"Apr"     → 15496
"ender"   → 2938
" IA"     → 8712
" es"     → 318
" genial" → 40021

Así, "Aprender IA es genial" se convierte en [15496, 2938, 8712, 318, 40021].

¿Por qué importan los tokens?

  • Los LLMs cobran por token (entrada + salida): saberlo ayuda a controlar costos.
  • Tienen un límite de tokens (ventana de contexto), ej. 128.000 tokens.
  • No pueden "leer" un libro infinito de una sola vez.
Por eso... A veces la IA "olvida" el inicio de una conversación muy larga: se salió de la ventana de contexto.

Embeddings: el mapa del significado

Un ID (como 8712) no dice nada sobre el significado. Necesitamos que palabras parecidas tengan números parecidos.

DefiniciónUn embedding es una lista de números (un vector) que representa el significado de un texto. Cientos o miles de dimensiones.
"perro" → [0.21, -0.98, 0.44, ..., 0.10]   (ej. 1024 números)
"gato"  → [0.19, -0.95, 0.40, ..., 0.12]   ← ¡muy parecido!
"avión" → [-0.80, 0.33, 0.91, ..., -0.55]  ← muy diferente

El significado como distancia

Imagina un mapa gigante donde cada palabra es un punto. Lo parecido queda cerca; lo diferente, lejos.

La similitud coseno mide qué tan cerca están dos vectores: un número entre -1 y 1 (cerca de 1 = muy parecidos).

      gato • • perro
  conejo •        • lobo


                      • avión
                  • helicóptero

Lo mágico de los embeddings

👑 − 👨 + 👩 ≈ 👸

rey − hombre + mujer ≈ reina

Los embeddings capturan relaciones. El modelo las aprende solo, a partir de los datos (aprendizaje autosupervisado de la Clase 1).

Práctica: medir significado con Cohere

Fragmento de clase-2/codigo/embeddings_similitud.py:

textos = ["perro", "gato", "avión", "cachorro"]
vectores = co.embed(
    texts=textos, model="embed-multilingual-v3.0",
    input_type="search_document").embeddings

def similitud(a, b):
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a)*np.linalg.norm(b)))

print("perro vs gato:    ", round(similitud(vectores[0], vectores[1]), 3))
print("perro vs cachorro:", round(similitud(vectores[0], vectores[3]), 3))
print("perro vs avión:   ", round(similitud(vectores[0], vectores[2]), 3))
Resultado"perro vs cachorro" y "perro vs gato" dan alto; "perro vs avión" da bajo. ¡El computador acaba de medir significado!

Transformers y atención

Los LLMs usan la arquitectura Transformer (2017, paper "Attention is All You Need"). Su superpoder es la atención.

El problema: el significado depende del contexto

  • "Fui al banco a sacar plata." → institución financiera.
  • "Me senté en el banco del parque." → asiento.

La misma palabra, significados distintos. ¿Cómo lo sabe el modelo? Mirando las otras palabras de la frase.

¿Qué hace la atención?

Para cada palabra, el modelo se pregunta: "¿a cuáles otras palabras debo prestar atención para entender esta?" y les asigna un peso.

"Me senté en el banco del parque"
                 ▲
                 └── presta MUCHA atención a "senté" y "parque"
                     → concluye: banco = asiento
Idea a retenerEl Transformer entiende cada palabra en función de todas las demás, ponderando cuáles son relevantes. Procesa todas a la vez, por eso es rápido.

Generación: predecir el siguiente token

Un LLM hace una sola cosa increíblemente bien: dado un texto, predice el token más probable que sigue. Luego lo agrega y repite.

Entrada: "El cielo es de color"
   "azul"  → 78%
   "gris"  → 12%
   "rojo"  →  4%
   "verde" →  1%
Elige "azul" → "El cielo es de color azul" → vuelve a predecir...
AutorregresivoSe alimenta de su propia salida. No hay base de datos de respuestas: todo se genera token a token.

La temperatura: creatividad vs. precisión

Temperatura baja (0 – 0.3) Elige casi siempre el token más probable. Respuestas precisas y repetibles. Ideal para datos, código, hechos.
Temperatura alta (0.8 – 1.5) Se arriesga con tokens menos probables. Respuestas creativas y variadas. Ideal para historias, lluvia de ideas.
¿Por qué "alucina"?Como siempre predice algo plausible, a veces genera algo que suena bien pero es falso. No tiene un verificador de verdad. Siempre verificar datos críticos.

El prompt: cómo le hablamos

El prompt es todo el texto de entrada que le damos. Un buen prompt = mejor respuesta.

Ingeniería de prompts básica

  1. Da contexto y rol: "Eres un profesor de matemáticas de primaria…".
  2. Sé específico: qué quieres, formato y longitud.
  3. Da ejemplos (few-shot): muéstrale 1–2 ejemplos de lo que esperas.
  4. Pídele pasos: "explica paso a paso" mejora el razonamiento.

Chunking + RAG: darle nuestros documentos

ProblemaEl LLM no conoce tus documentos privados (manual de tu empresa, tus apuntes) y no cabe un libro entero por el límite de tokens.

RAG = Retrieval-Augmented Generation (Generación Aumentada por Recuperación).

IdeaPrimero buscamos los fragmentos relevantes de nuestros documentos y se los pasamos al LLM junto con la pregunta. El LLM responde basándose en ellos.

El pipeline de RAG

PREPARACIÓN (una sola vez):
  Documento grande
    │ 1. CHUNKING: partir en trozos (chunks)
    │ 2. EMBEDDINGS: vectorizar cada chunk
    ▼
  [vec1][vec2][vec3]... → BASE DE DATOS VECTORIAL

CONSULTA (cada pregunta):
  Pregunta → 3. vectorizar → 4. BUSCAR chunks más cercanos
    ▼
  chunks relevantes + pregunta → 5. PROMPT al LLM → respuesta
BD vectorialGuarda vectores y busca los más parecidos rapidísimo. Ej: Chroma, FAISS, Pinecone, Weaviate.

¿Qué es el chunking?

Chunking = partir un documento grande en trozos manejables antes de vectorizarlos.

  • Chunk muy grande: mezcla temas, el embedding se vuelve "borroso".
  • Chunk muy pequeño: pierde contexto.
  • Solapamiento (overlap): los chunks comparten un poco de texto en los bordes para no cortar ideas.
"...la fotosíntesis convierte luz en energía. Las plantas usan clorofila..."
 └──────── chunk 1 ────────┘
                  └──────── chunk 2 ────────┘  (con solapamiento)

Práctica: mini-RAG casero

Fragmento de clase-2/codigo/mini_rag.py:

chunks = [
    "El horario de atención del SENA es de lunes a viernes de 7am a 5pm.",
    "El curso de IA se dicta los sábados de 8am a 12m en Piedecuesta.",
    "Para certificarse se requiere el 80% de asistencia.",
]
emb_chunks = co.embed(texts=chunks, model="embed-multilingual-v3.0",
                      input_type="search_document").embeddings

pregunta = "¿A qué hora es la clase de inteligencia artificial?"
emb_preg = co.embed(texts=[pregunta], model="embed-multilingual-v3.0",
                    input_type="search_query").embeddings[0]

puntajes = [similitud(emb_preg, e) for e in emb_chunks]
mejor = int(np.argmax(puntajes))
print("Chunk más relevante:", chunks[mejor])
ResultadoDevuelve el chunk del horario de la clase. Esto es RAG en su forma más simple.

El pipeline completo de un LLM

TEXTO
  │ Tokenización         → [tokens] → [IDs numéricos]
  │ Embeddings           → cada token/frase = vector de significado
  │ Transformer+Atención → entiende cada token según el contexto
  │ Generación           → predice el siguiente token, uno a uno (temperatura)
  ▼
LENGUAJE NATURAL de salida

(+ RAG: chunking → embeddings → BD vectorial → búsqueda → contexto extra)
