Chatbot vs. Agente

Chatbot simpleRecibe un mensaje y responde. No recuerda, no actúa, no consulta nada fuera del modelo.
AgenteRazona, decide y actúa para cumplir un objetivo, usando recursos externos: memoria, herramientas y datos.
En una fraseUn agente es un LLM al que le damos memoria + herramientas + un bucle para resolver tareas, no solo para conversar.

Anatomía de un agente

  1. LLM (el cerebro): decide qué hacer y genera lenguaje. (Gemini / Cohere).
  2. Memoria: recuerda la conversación y los hechos. (Historial + RAG).
  3. Herramientas (tools): funciones que puede llamar: calcular, buscar, consultar una base de datos, enviar un correo…
  4. Bucle de razonamiento: pensar → actuar → observar → repetir hasta resolver la tarea.
Ya lo conocesOpenCode (Clase 0) es justo esto: un LLM + herramientas (leer/escribir archivos, ejecutar comandos) + memoria del proyecto.

El patrón ReAct (Reason + Act)

La mayoría de los agentes siguen este ciclo de razonar y actuar:

Pensamiento: necesito saber el clima de hoy.
Acción:      llamar herramienta buscar_clima("Piedecuesta")
Observación: "24°C, soleado"
Pensamiento: ya tengo la info, puedo responder.
Respuesta:   "Hoy en Piedecuesta hay 24°C y está soleado."
ClaveEl modelo alterna entre pensar y usar herramientas hasta tener todo lo que necesita para responder bien.

Proyecto 1

Chatbot con memoria de conversación usando Gemini

8:50 – 9:40

Chatbot con memoria (Gemini)

Un modelo por defecto no recuerda el mensaje anterior. La "memoria" se logra enviándole el historial en cada turno.

pip install google-generativeai python-dotenv
La pieza mágicaEl método .start_chat() mantiene el historial automáticamente = MEMORIA.

Proyecto 1 — el código

import os
from dotenv import load_dotenv
import google.generativeai as genai

load_dotenv()
genai.configure(api_key=os.getenv("GEMINI_API_KEY"))

modelo = genai.GenerativeModel(
    "gemini-1.5-flash",
    system_instruction="Eres un tutor amable del SENA. Respondes claro y corto."
)

# start_chat mantiene el historial = MEMORIA
chat = modelo.start_chat(history=[])

while True:
    mensaje = input("Tú: ")
    if mensaje.lower() == "salir":
        break
    print("Tutor:", chat.send_message(mensaje).text)

Proyecto 2

🛠️

Agente con herramientas (function calling)

9:55 – 10:45

Agente con herramientas

Los LLMs son malos en matemáticas exactas y no conocen datos en tiempo real. Solución: darles herramientas (funciones de Python) que ellos deciden cuándo llamar.

La idea centralUna herramienta puede ser CUALQUIER función de Python. El docstring le dice al modelo qué hace y cuándo usarla.
Nombre técnicoEsto se llama function calling o tool use.

Proyecto 2 — el código

# 1. Herramientas = funciones normales de Python
def calcular(operacion: str) -> str:
    """Evalúa una operación matemática. Ej: '15 * 23 + 7'."""
    return str(eval(operacion, {"__builtins__": {}}, {}))

def clima(ciudad: str) -> str:
    """Devuelve el clima (simulado) de una ciudad."""
    datos = {"piedecuesta": "24°C, soleado", "bogota": "14°C, lluvioso"}
    return datos.get(ciudad.lower(), "No tengo datos de esa ciudad.")

# 2. Le entregamos las herramientas al modelo
modelo = genai.GenerativeModel("gemini-1.5-flash", tools=[calcular, clima])
chat = modelo.start_chat(enable_automatic_function_calling=True)

# 3. El modelo DECIDE solo cuándo usar cada herramienta
print(chat.send_message("¿Cuánto es 1520 * 34?").text)
print(chat.send_message("¿Y qué clima hace en Piedecuesta?").text)

Archivo completo: clase-4/codigo/2_agente_herramientas.py

¿Qué verá el grupo?

  • El aprendiz pregunta en lenguaje natural.
  • El modelo entiende que debe usar calcular o clima.
  • Llama la función, recibe el resultado y responde con él.
Independiente del proveedorCohere también soporta tool use con co.chat(tools=...). Se declaran las herramientas y el modelo pide ejecutarlas: el concepto de agente es el mismo.

Agente RAG con datos propios

Unimos el RAG de la Clase 2 con un agente que responde solo con nuestros documentos. Caso real: un asistente del reglamento del SENA.

RAG = Retrieval-Augmented Generation:

  1. Vectorizar los documentos una vez (embeddings).
  2. Buscar los fragmentos más parecidos a la pregunta (retrieval).
  3. Generar la respuesta usando SOLO esos fragmentos (generation).
pip install cohere numpy python-dotenv

Proyecto 3 — el código

documentos = [
    "El curso de IA del SENA Piedecuesta es los sábados de 8am a 12m.",
    "Se requiere 80% de asistencia para certificarse.",
    "El instructor del curso es Andrés Carvajal.",
]
# Vectorizamos la base una sola vez
emb_docs = co.embed(texts=documentos, model="embed-multilingual-v3.0",
                    input_type="search_document").embeddings

def responder(pregunta):
    emb_p = co.embed(texts=[pregunta], model="embed-multilingual-v3.0",
                     input_type="search_query").embeddings[0]
    ranking = sorted(range(len(documentos)),
                     key=lambda i: similitud(emb_p, emb_docs[i]), reverse=True)
    contexto = "\n".join(documentos[i] for i in ranking[:2])
    prompt = (f"Usa SOLO esta información.\n{contexto}\n\n"
              f"Pregunta: {pregunta}\nSi no está, di que no la tienes.")
    return co.chat(message=prompt, model="command-r").text

Seguridad de las claves — ¡crítico!

  1. Las claves van en .env, NUNCA en el código.
  2. Crear un archivo .gitignore para que .env nunca se suba a GitHub.
# .gitignore
.env
__pycache__/
*.pkl
Si una clave se filtraRevócala y genera una nueva de inmediato desde el panel del proveedor.

Límites, costos y despliegue

Límites y costos

  • Las APIs gratuitas tienen límites por minuto y cupos.
  • Los LLMs cobran por token: prompts más cortos = más barato.
  • Elige el modelo más pequeño que sirva (flash, command-r).
