¿Qué es esta sesión?

ImportanteLa Clase 0 no es una clase con horario: es una preparación rápida para dejar el entorno listo. Así, en la Clase 1 arrancamos directo con el contenido.

Lo que dejaremos listo:

  • Cuentas y claves de API: Google AI Studio (Gemini), Cohere y GitHub.
  • Python y VS Code instalados.
  • OpenCode conectado a una API gratuita.
  • Claves guardadas de forma segura (archivo .env).
  • Nuestra primera petición a un modelo de IA desde código.

¿Qué es una API?

Analogía del restaurante:

  • El modelo de IA es la cocina.
  • Tú eres el cliente en la mesa.
  • La API es el mesero: lleva tu pedido y trae la respuesta.

No necesitas entrar a la cocina ni saber cómo cocinan.

Idea clave Una API es la forma en que un programa le "pide" algo a otro. Nosotros le pedimos respuestas a la IA sin tenerla instalada en el PC.

¿Qué es una API key?

Es tu tarjeta de cliente: identifica quién hace el pedido, para medir y limitar el uso.

Regla de oro Una API key es personal y secreta, como la clave de tu tarjeta débito. Nunca se comparte, nunca se sube a internet, nunca se pega en un chat público.

¿Por qué usamos modelos en la nube?

Los LLMs grandes necesitan hardware que cuesta miles de dólares (GPUs). Con la API le "alquilamos" ese poder a Google o Cohere y usamos su nivel gratuito.

3 palabras que vas a oír: SDK, librería y repo

📚 Librería

Un conjunto de código listo para una tarea concreta. La importas y la usas.

Ej.: numpy (matemáticas), requests (internet).

🧰 SDK

Un kit completo para trabajar con una plataforma: normalmente incluye una o varias librerías + herramientas + ejemplos. Suele ser oficial del proveedor.

Ej.: el SDK de google-generativeai (Gemini), el de cohere.

🗄️ Repo (repositorio)

El lugar donde se guarda y versiona el código (con Git, por ejemplo en GitHub). Adentro puede haber una librería, un SDK o una app entera.

La diferencia, con una analogía

ConceptoAnalogía (taller)
LibreríaUna herramienta (un destornillador): hace una tarea.
SDKUna caja de herramientas completa para un trabajo, con manual e instrucciones.
RepoEl estante/bodega donde guardas y ordenas todo, con su historial de cambios.
En resumenUn SDK suele contener librerías; un repo es donde vive el código de cualquiera de los dos.

Guardar las claves de forma segura

Creamos un archivo llamado .env (lo usaremos en el código):

NuncaEl archivo .env guarda secretos y jamás se sube a GitHub. Se agrega a .gitignore (lo vemos en la Clase 4).

OpenCode: programar con ayuda de IA

OpenCode es un agente de IA de código abierto que vive en la terminal. Le escribes en lenguaje natural y él lee, escribe y modifica archivos de tu proyecto.

Lo mejorFunciona con APIs gratuitas (Gemini, Cohere, GitHub Models). No estás obligado a pagar.
Conexión con el cursoOpenCode es un ejemplo vivo de un agente de IA (LLM + herramientas + acción). ¡Es lo que construiremos en la Clase 4!

Instalar y usar OpenCode

npm install -g opencode-ai

Si no tienes Node.js, instálalo desde nodejs.org (versión LTS). Verificar:

opencode --version
  1. Entrar a una carpeta de proyecto y ejecutar opencode.
  2. Elegir proveedor (Gemini o Cohere) y pegar la API key.
  3. Elegir un modelo gratuito (ej. gemini-1.5-flash).

La TUI: la interfaz de OpenCode

OpenCode vive en la terminal (TUI = Text User Interface). No necesitas mouse: todo se maneja con texto y atajos.

  • Escribes tu petición en lenguaje natural y OpenCode actúa.
  • Los comandos empiezan con / (por ejemplo /help, /new, /undo, /share).
  • Muestra en vivo qué archivos lee y modifica y cuántos tokens lleva usados.
VentajasEs gratis y de código abierto, funciona con casi cualquier modelo, no te encierra en un solo proveedor y corre en cualquier sistema.

Atajos de teclado esenciales

OpenCode usa una tecla líder (leader): Ctrl+X. Pulsas Ctrl+X y luego otra tecla (tienes 2 segundos).

Dos superpoderes: @ y !

@ — mencionar archivos

Escribe @ y busca un archivo del proyecto para dárselo como contexto a la IA.

Explícame qué hace @app.py
y corrige el error de @utils/db.py

Así la IA lee solo esos archivos, sin que copies y pegues.

! — ejecutar en la terminal

Empieza el mensaje con ! para correr un comando del sistema; su salida entra a la conversación.

!python app.py
!git status
!pip install requests
Tip@ = "mira este archivo" · ! = "ejecuta esto" · / = "comando de OpenCode".

Dos modos clave: Build y Plan

🛠️ Build

Modo normal: OpenCode crea y modifica archivos, ejecuta comandos y construye lo que pides.

🧭 Plan

Modo restringido: antes de editar archivos o ejecutar comandos siempre te pregunta. Ideal para analizar y planear sin riesgo.

Cómo cambiar de modoPulsa Tab para alternar Build ⇄ Plan (Shift+Tab para volver). Con Ctrl+X luego a ves la lista de modos/agentes. Buena práctica: primero Plan, luego Build.

Modo Shell y el historial

  • Modo Shell: puedes ejecutar comandos de terminal (instalar, correr el programa, git…) sin salir de OpenCode.
  • El historial importa: OpenCode recuerda el contexto de la sesión. Ese "recuerdo" es lo que le permite continuar una tarea larga… pero también gasta tokens.
ConexiónEse "recuerdo" es la memoria de un agente y ese "contexto" son tokens: dos ideas centrales de las Clases 2 y 4.

Ahorrar tokens (y dinero)

Cada mensaje envía contexto al modelo, y el contexto cuesta tokens. Para gastar menos:

  • Empieza una sesión nueva (/new) cuando cambies de tema; no arrastres historial innecesario.
  • Sé específico y breve: pide exactamente lo que necesitas.
  • Usa Plan para acordar antes de generar mucho código a ciegas.
  • Vigila el porcentaje de contexto usado que muestra la TUI.
ReglaMenos contexto = respuestas más rápidas y baratas.

Flujo de un proyecto real

OpenCode brilla al construir algo de principio a fin:

  • SPEC.md: un archivo donde describes qué quieres construir. OpenCode lo usa como guía.
  • Tareas agrupadas: divide el trabajo en pasos y los va completando.
  • Timeline: ver el avance y los cambios hechos.
  • Revertir cambios: si algo salió mal, se deshace (/undo) y vuelves a un punto anterior.
ResultadoSe puede pasar de una idea a una aplicación que funciona (incluso un servidor y una web).

El archivo SPEC.md

Describe QUÉ quieres construir, con detalle, antes de programar. Es una buena práctica (no una función oficial de OpenCode).

Flujo recomendado

  1. Escribe el SPEC.md: objetivo, funcionalidades y criterios de aceptación.
  2. En modo Plan: Lee @SPEC.md y propón un plan.
  3. Revisas el plan → cambias a Build y lo construye paso a paso.
  4. Verificas cada criterio de aceptación.

Personalizar OpenCode

Tema y notificaciones

Cambia los colores de la TUI y activa avisos cuando termina una tarea larga.

AGENTS.md

Un archivo en tu proyecto con reglas e instrucciones para el agente (estilo de código, cómo correr las pruebas, qué evitar). OpenCode lo lee siempre.

IdeaAGENTS.md es como el "manual de la casa" que el agente respeta en cada tarea.

Crear un AGENTS.md

Archivo con reglas para el asistente. OpenCode lo lee solo en cada sesión: el "manual de la casa" del proyecto.

Dónde va

  • AGENTS.md en la raíz del proyecto (lo común)
  • ~/.config/opencode/AGENTS.md (global)

Cómo crearlo

Ejecuta /init: revisa tu proyecto y lo genera. O créalo a mano.

Qué escribir

  • Descripción y tecnologías
  • Estructura de carpetas
  • Cómo ejecutar y probar
  • Convenciones (idioma, estilo)
  • Qué evitar

Comandos, agentes y skills

  • Comandos propios: creas atajos para tareas repetidas (por ejemplo, "genera un componente con este formato").
  • Agentes: puedes usar sub-agentes especializados para distintas partes del trabajo.
  • Skills (AgentSkill): "habilidades" empaquetadas que le enseñan a OpenCode a hacer algo específico (ej. crear videos con HTML/CSS/JS).
  • Argumentos: los comandos pueden recibir parámetros para reutilizarlos.
AnticipoComandos + agentes + skills = personalizar el comportamiento de un agente. Justo lo que exploraremos en la Clase 4.

Crear un comando propio

Un comando es un archivo .md. El nombre del archivo es el comando.

# archivo: componente.md   →   crea el comando /componente
---
description: Crea un componente de React
---
Crea un componente de React llamado $ARGUMENTS con
TypeScript, tipado correcto y una estructura básica.

Se usa: /componente Boton

Argumentos$ARGUMENTS recibe todo lo que escribas; también $1, $2… por posición.

Comando local vs. remoto (compartido)

🏠 Local (del proyecto)

Carpeta .opencode/commands/ dentro del proyecto. Solo existe en ese proyecto.

🌍 Global (de tu usuario)

Carpeta ~/.config/opencode/commands/. Disponible en todos tus proyectos de esa máquina.

🔗 "Remoto" = compartirlo con el equipo

OpenCode no baja comandos desde una URL. Para que otros los tengan, sube la carpeta .opencode/ a un repositorio Git (GitHub); al clonar el repo, todos reciben los comandos.

TambiénPuedes definirlos en el archivo opencode.json (campo command).

Comandos avanzados: @ y !

Dentro del comando puedes incluir archivos (@) y meter la salida de la terminal (!`...`):

# archivo: revisar-tests.md   →   /revisar-tests
---
description: Ejecuta las pruebas y sugiere mejoras
---
Estos son los resultados de las pruebas:
!`npm test`

Revisa también el componente @src/components/Boton.tsx
y, según los resultados, sugiere mejoras.
IdeaEl comando arma un prompt "inteligente": corre algo real y adjunta archivos, sin que copies y pegues.

Ejemplo: crear un agente propio

La forma fácil: un asistente te guía paso a paso.

opencode agent create

O créalo a mano en .opencode/agents/ (el nombre del archivo es el agente):

# archivo: .opencode/agents/documentador.md
---
description: Escribe y mantiene la documentación del proyecto
mode: subagent
permission:
  bash: deny
---
Eres un redactor técnico. Escribe documentación clara,
bien estructurada y con ejemplos de código.
Modosprimary (lo usas con Tab) o subagent (lo llama otro agente para una tarea).

Ejemplo: crear una skill

Una skill es una habilidad empaquetada. Va en .opencode/skills/<nombre>/SKILL.md.

# archivo: .opencode/skills/notas-version/SKILL.md
---
name: notas-version
description: Crea notas de versión y changelog consistentes
---
## Qué hago
- Redacto notas de versión a partir de los PR combinados
- Propongo el nuevo número de versión
- Doy un comando `gh release create` listo para copiar

## Cuándo usarme
Cuando estés preparando una nueva versión etiquetada.
Cómo se activaEl agente la usa sola cuando la description coincide con lo que pides.

Sesiones y formas de ejecutarlo

  • Cambiar entre sesiones: mantén varias conversaciones/proyectos y salta entre ellas.
  • Compartir sesiones: genera un enlace para mostrar lo que hiciste (/share).
  • Desde la terminal: además del modo interactivo, puedes lanzar tareas directas y levantar un servidor.
CuidadoAl compartir una sesión se publica su contenido en internet. No compartas nada con claves o datos privados.

Modelos y modelos de pago

  • OpenCode funciona con muchos proveedores: gratuitos (Gemini, Cohere, GitHub Models) y de pago.
  • Puedes conectar tu propia suscripción/clave y elegir el modelo por tarea.
  • Distintos modelos tienen distinta calidad, velocidad y costo: conviene compararlos.
Para el cursoCon los planes gratuitos es más que suficiente. Los modelos de pago (mejor calidad) quedan como algo opcional para más adelante.

Conectar una suscripción (ChatGPT)

Además de una API key, puedes iniciar sesión con una suscripción ya existente.

  1. En OpenCode escribe /connect.
  2. Elige el proveedor OpenAI y la opción "ChatGPT Plus/Pro".
  3. Se abre el navegador para iniciar sesión y autorizar.
TambiénSoporta GitHub Copilot y GitLab Duo con suscripción. Las credenciales se guardan en ~/.local/share/opencode/auth.json.
OjoAnthropic no permite usar Claude Pro/Max en herramientas de terceros. Para Claude, usa una API key.

Pagar OpenCode (OpenCode Zen)

OpenCode Zen es el servicio del equipo de OpenCode: una lista de modelos probados, con pago por uso (por tokens) y también algunos gratuitos.

  1. Inicia sesión en OpenCode Zen y agrega tus datos de facturación (tarjeta).
  2. Obtén tu API key de Zen.
  3. En OpenCode: /connect → elige OpenCode Zen → pega la key.
  4. Elige el modelo con el formato opencode/<modelo>.
Para el cursoNo es necesario pagar: con las APIs gratuitas (Gemini/Cohere) basta. Zen es opcional para más adelante.

Buenas prácticas con OpenCode

  • Plan primero, luego Build (Tab para cambiar).
  • Usa un AGENTS.md desde el inicio (/init).
  • Escribe un SPEC.md para proyectos con varias partes.
  • Sé específico y da contexto con @ en vez de copiar y pegar.
  • Pasos pequeños y revisa cada cambio (/undo si algo falla).
  • Ahorra tokens: /new al cambiar de tema, /compact en charlas largas.
  • Usa Git y nunca subas claves (.env en .gitignore).
SiempreLee y prueba lo que genera la IA: puede equivocarse con total seguridad.

Práctica: "Hola IA" desde Python

import os
from dotenv import load_dotenv
import google.generativeai as genai

load_dotenv()
genai.configure(api_key=os.getenv("GEMINI_API_KEY"))
modelo = genai.GenerativeModel("gemini-1.5-flash")

respuesta = modelo.generate_content(
    "Explícame en una frase qué es la inteligencia artificial.")
print(respuesta.text)
