LLM: el "autocompletar" gigante

Un LLM (Large Language Model) es un modelo entrenado con muchísimo texto. Su único truco:

Su superpoderDado un texto, predice qué texto sigue.

De ese truco salen: conversar, resumir, traducir, escribir código y "razonar".

Token: la moneda del LLM

El modelo no lee letras ni palabras: lee tokens (trozos de texto, ≈ 4 caracteres en promedio).

"Piedecuesta"
→
Pie|de|cu|esta≈ 4 tokens

💰 Se cobra

Por tokens de entrada (lo que envías) y de salida (lo que responde).

🚦 Se limita

Cuota por minuto/día en planes gratuitos (error 429).

📏 Tiene techo

La ventana de contexto: máximo de tokens que cabe en una llamada.

Temperatura y otros "diales"

🌡️ temperatura

0 = serio y repetible.
1 = creativo e impredecible.

Agentes → usa 0 a 0.3. Quieres decisiones estables.

✂️ max tokens

Corta la respuesta. Protege tu costo y tu tiempo.

🧾 modo JSON

Fuerza al modelo a responder JSON. Clave para que tu código entienda al LLM.

Idea claveUn agente es código que lee la respuesta del LLM y actúa. Por eso necesitamos respuestas predecibles y parseables.

Top-k y Top-p: recortar las opciones

El modelo puede descartar las palabras poco probables antes de sortear. "La playa es …" con k = 2 y p = 0.83:

PalabraProb.Acumul.Top-k 2Top-p .83
beautiful28 %28 %✅✅
clear22 %50 %✅✅
perfect15 %65 %❌✅
lovely10 %75 %❌✅
warm7 %82 %❌✅
bright6 %88 % ≥ 83❌✅ (fin)

🔢 Top-k

Deja solo las k más probables: con k = 2, beautiful y clear.

📊 Top-p (núcleo)

Deja las más probables hasta sumar al menos p: con p = 0.83 son 6 palabras (88 %).

Cómo usarlosValores bajos = más predecible. Ajusta temperatura o top-p, no ambos. En agentes: temperatura 0–0.3 y lo demás por defecto.

Herramienta (tool): las manos del LLM

El LLM solo produce texto. No puede consultar el clima, sumar con exactitud ni saber qué hora es. Una herramienta es una función normal de tu código que el LLM puede pedir que ejecutes.

🧠 LLM"Necesito el clima de Cali"
→
⚙️ Tu códigoejecuta clima("Cali")
→
📦 Resultado"27 °C, soleado"
→
🧠 LLMredacta la respuesta
OjoEl LLM no ejecuta nada: solo pide. Quien ejecuta (y puede negarse) eres tú. Ahí vive la seguridad.

¿Qué es un agente de IA?

Definición de trabajoUn agente es un programa que usa un LLM para decidir qué hacer, ejecuta acciones con herramientas, mira el resultado y repite en un bucle hasta cumplir un objetivo.

🎯 Objetivo

Una tarea abierta, no un solo paso.

🔁 Bucle

Pensar → actuar → observar → repetir.

🛠️ Herramientas

Su forma de tocar el mundo real.

Truco para recordar: agente = LLM + herramientas + bucle + (memoria).

La escalera de agentes

0 Llamada simple LLM como función
1 Chatbot con memoria rol + historial
2 Agente con herramientas 1 herramienta por pregunta
3 Agente ReAct bucle de herramientas
4 Planificador plan → ejecutar → sintetizar
5 Multi-agente orquestador + especialistas

Cada nivel agrega una capacidad y también un riesgo. Sube solo cuando el nivel actual no alcance.

¿Qué agrega cada nivel?

NivelAgregaÚsalo para…Riesgo
0—Resumir, traducir, clasificarAlucina datos
1Rol + memoriaAsistentes, tutores, FAQHistorial caro/largo
2Herramientas (1 vez)"¿Qué hora es?", cálculo, consulta puntualNo encadena pasos
3Bucle ReActPreguntas que necesitan 2+ herramientasBucles, costo variable
4Plan explícitoTareas largas y revisablesPlan malo = todo malo
5EspecialistasDominios distintos, equiposComplejidad y latencia

El problema: depender de un solo proveedor

❌ Sin patrón

if (prov === "gemini") {
  // formato Gemini...
} else if (prov === "cohere") {
  // formato Cohere...
} else if (prov === "groq") {
  // formato Groq...
}
// ...repetido en CADA agente 😱

Consecuencias

  • Cambiar de proveedor = reescribir todo.
  • Cuota agotada → la app se cae.
  • Imposible hacer pruebas sin gastar.
  • Cada if nuevo rompe algo.
RealidadLos proveedores cambian precios, modelos y límites cada mes.

Patrón Strategy: piezas intercambiables

La ideaDefine una interfaz común y haz que cada variante sea una clase que la cumple. El resto del código solo conoce la interfaz.

🚗 Analogía: el GPS

Misma app, distintas "estrategias" de ruta: más rápida, más corta, sin peajes. Tú eliges, la app no cambia.

🔌 Analogía: el enchufe

Tu laptop no sabe si la energía viene de una hidroeléctrica o de un panel solar. Solo exige el enchufe.

💳 Analogía: pagos

El carrito de compras llama pagar(). Detrás puede ser tarjeta, PSE o Nequi.

Paso 1 · La interfaz (el "enchufe")

// src/llm/types.ts
export interface Mensaje {
  rol: "system" | "user" | "assistant";
  contenido: string;
}

export interface LLMProvider {
  readonly nombre: string;
  chat(mensajes: Mensaje[], opciones?: OpcionesChat): Promise<string>;
}
Qué notarEntra una lista de mensajes nuestra, sale un string. Cada proveedor traduce de/hacia su formato propio. Nadie más lo sabrá.

Paso 2 · Una estrategia concreta (Groq)

export class GroqProvider implements LLMProvider {
  readonly nombre = "groq";
  constructor(private apiKey: string,
              private modelo = "llama-3.3-70b-versatile") {}

  async chat(mensajes: Mensaje[], op: OpcionesChat = {}) {
    const data = await postJson("groq",
      "https://api.groq.com/openai/v1/chat/completions",
      { Authorization: `Bearer ${this.apiKey}` },
      { model: this.modelo,
        messages: mensajes.map(m => ({ role: m.rol, content: m.contenido })),
        temperature: op.temperatura ?? 0.3 });
    return data.choices[0].message.content;   // ← el texto
  }
}

Gemini cambia assistant→model y separa el system; Cohere usa otra URL. Esas diferencias quedan encapsuladas aquí.

⚠️ Seguridad: jamás eval()

Peligroso

ejecutar: (expr) => eval(expr)

// Un texto manipulado puede pedir:

Correcto

// calculadora.ts: parser propio

PrincipioTodo lo que sale de un LLM es entrada no confiable, igual que un formulario web. Valida, limita, nunca ejecutes a ciegas.

El protocolo JSON (funciona en los 3 proveedores)

Le pedimos al LLM que SIEMPRE responda con uno de dos formatos:

4

Agente ReAct

Nivel 3: aquí nace un agente de verdad.

⏱ 50 min · incluye Actividad 3

El bucle completo (resumen)

for (let paso = 1; paso <= maxPasos; paso++) {
  const crudo = await llm.chat(mensajes, { json: true, temperatura: 0 });

  let decision;
  try { decision = interpretar(crudo); }                // 🛡️ defensa 1
  catch { /* pedir que corrija el formato */ continue; }

  if (decision.tipo === "final") return decision.respuesta;   // ✅ fin

  if (yaLoHizo(decision)) { /* avisar: no repitas */ }        // 🛡️ defensa 2
  else obs = await herramientas.ejecutar(decision.accion, decision.entrada);

  mensajes.push(asistente(crudo), usuario(`Observación: ${obs}`)); // 🔁
}
return "No pude terminar en maxPasos";                         // 🛡️ defensa 3

La regla de oro: el nivel más bajo que funcione

? ¿Necesitas varios pasos que no conoces de antemano? → Nivel 3+
? ¿Necesitas consultar algo externo una vez? → Nivel 2
? ¿Es solo conversar con contexto? → Nivel 1
? ¿Es una transformación de texto? → Nivel 0
CuidadoUn agente complejo donde bastaba un if es más lento, más caro, menos predecible y más difícil de depurar. Un buen ingeniero sabe cuándo no usar IA.

Lo que te llevas

  • Un LLM es una función sin memoria; un agente es código que lo usa en un bucle con herramientas.
  • Strategy te libera del proveedor: Gemini, Cohere, Groq, Mock y combinaciones (Fallback, Medido).
  • Seis niveles: llamada → memoria → herramienta → ReAct → plan → multi-agente.
  • Administrar = límites + trazas + seguridad + resiliencia + pruebas.
  • Usa siempre el nivel más bajo que resuelva el problema.
