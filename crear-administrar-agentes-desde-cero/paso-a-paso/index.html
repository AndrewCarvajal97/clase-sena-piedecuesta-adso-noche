Crear agentes de IA desde cero, paso a paso

De un script vacío a un equipo de agentes: TypeScript + Node + Strategy (Gemini · Cohere · Groq)

🧭 Cómo usar esta guía

Modo A · Programar en vivo (recomendado)
Crea la carpeta del proyecto y avanza paso a paso: lee la sección «Qué problema resuelve», escribe los archivos de «Qué crear» (puedes copiarlos con el botón) y ejecuta los comandos. Compara tu salida con «Debes ver».
Modo B · Checkpoints (para no quedarte atrás)
La carpeta checkpoints/paso-NN contiene el proyecto COMPLETO tal como queda al terminar cada paso. Si un aprendiz se pierde, copia el checkpoint, ejecuta npm install y continúa desde ahí.
Modo C · Solo lectura
Cada paso explica el porqué de cada archivo con las líneas importantes señaladas. Sirve para repasar o para preparar tu clase.

🧱 Principios

  • Un paso = una capacidad nueva. Cada paso agrega UNA idea y termina con algo que se ejecuta y se ve funcionando.
  • Primero el problema, luego el código. Antes de escribir nada se explica qué duele sin esa pieza. Así el código se entiende como solución, no como magia.
  • Siempre sin claves. Todo funciona con LLM_PROVIDER=mock (sin internet ni gastar cuota). Los proveedores reales se conectan en el paso 3 y no cambian ni una línea de los agentes.
  • Sin frameworks. Solo TypeScript, Node y fetch. Así se ve qué hace realmente un agente por dentro.
  • Cada paso está verificado. Un generador construye cada checkpoint, comprueba que compile con tsc y ejecuta los comandos para capturar la salida real que ves en cada paso.

Paso 1 · El contrato LLMProvider y un LLM de mentira

Definir la interfaz común de todos los LLM y crear el primer «proveedor»: un mock que funciona sin internet.

❓ Qué problema resuelve

Cada proveedor (Gemini, Cohere, Groq) usa un formato distinto. Si tu agente habla directamente con uno, cambiar de proveedor significa reescribir todo, y no puedes practicar sin internet ni gastar cuota. La solución es definir UNA interfaz y que todo dependa de ella: el patrón Strategy.

🧠 Conceptos clave

Patrón Strategy
Varias clases intercambiables que cumplen la misma interfaz. El agente solo conoce la interfaz, nunca la clase concreta.
Mensaje y roles
Una conversación es una lista de mensajes con rol: system (reglas), user (la persona) y assistant (el modelo).
Mock
Un «LLM falso» con reglas simples. Permite desarrollar, probar y dar la clase sin claves ni internet.

🆕 Nuevosrc/llm/types.ts

Por qué: El contrato. Define cómo se ve un mensaje y qué debe saber hacer cualquier LLM: recibir mensajes y devolver texto.

  • Mensaje { rol, contenido } es NUESTRO formato único. Cada proveedor lo traducirá al suyo.
  • LLMProvider solo tiene dos miembros: nombre y chat(). Entra una lista de mensajes, sale TEXTO. Es todo lo que un agente necesita.
  • OpcionesChat: temperatura, maxTokens y json, que casi todos los modelos entienden.
  • ErrorLLM: un error propio para distinguir fallos de red/API de nuestros bugs (lo usaremos en reintentos y fallback).
Código
/**
 * ============================================================
 *  PATRÓN STRATEGY — la interfaz común de TODOS los LLM
 * ============================================================
 *  Idea: el agente NO sabe si habla con Gemini, Cohere o Groq.
 *  Solo sabe que existe algo con un método `chat()`.
 *  Cada proveedor es una "estrategia" intercambiable.
 */

/** Quién habla en la conversación. */
export type Rol = "system" | "user" | "assistant";

/** Un mensaje de la conversación. */
export interface Mensaje {
  rol: Rol;
  contenido: string;
}

/** Opciones que casi todos los LLM entienden. */
export interface OpcionesChat {
  /** 0 = muy predecible, 1 = más creativo. */
  temperatura?: number;
  /** Límite de tokens de la respuesta. */
  maxTokens?: number;
  /** Pedirle al modelo que responda SOLO JSON (si el proveedor lo soporta). */
  json?: boolean;
}

/** Contrato que cumple cada estrategia (Gemini, Cohere, Groq, Mock…). */
export interface LLMProvider {
  /** Nombre legible, útil para logs y comparaciones. */
  readonly nombre: string;
  /** Recibe la conversación y devuelve el TEXTO de la respuesta. */
  chat(mensajes: Mensaje[], opciones?: OpcionesChat): Promise<string>;
}

/** Error propio para distinguir fallos de red / API del resto. */
export class ErrorLLM extends Error {
  constructor(
    public readonly proveedor: string,
    mensaje: string,
    public readonly status?: number,
  ) {
    super(`[${proveedor}] ${mensaje}`);
    this.name = "ErrorLLM";
  }
}
🆕 Nuevosrc/llm/providers/mock.ts

Por qué: Nuestra primera estrategia concreta. No es inteligente: responde con reglas simples. Sirve para desarrollar sin internet, hacer pruebas repetibles y no gastar cuota.

  • implements LLMProvider: TypeScript obliga a cumplir el contrato; si olvidas chat() no compila.
  • conversar(): si en el historial hay «me llamo X» y preguntan «¿cómo me llamo?», responde X. Así demostraremos que la «memoria» es el historial que TÚ reenvías.
  • Por ahora solo conversa. El mock crecerá en cada paso para entender cada nueva capacidad.
Código
import type { LLMProvider, Mensaje } from "../types.js";

interface OpcionesMock {
  /** Nombre visible (útil cuando creas varios mocks). */
  etiqueta?: string;
}

/**
 * Estrategia #4 — Mock: un "LLM falso" que funciona SIN internet y SIN claves.
 * No es inteligente: usa reglas simples y reconoce el protocolo de nuestros agentes.
 * Sirve para: practicar sin gastar cuota, hacer pruebas y entender el flujo.
 */
export class MockProvider implements LLMProvider {
  readonly nombre: string;
  constructor(private readonly op: OpcionesMock = {}) {
    this.nombre = op.etiqueta ?? "mock";
  }

  async chat(mensajes: Mensaje[]): Promise<string> {
    return this.conversar(mensajes);
  }

  // ---------- Conversación normal (niveles 0 y 1) ----------
  private conversar(msgs: Mensaje[]): string {
    const ultimo = msgs.filter((m) => m.rol === "user").at(-1)?.contenido ?? "";
    if (/c[oó]mo me llamo|cu[aá]l es mi nombre/i.test(ultimo)) {
      const dicho = msgs
        .map((m) => /(?:me llamo|mi nombre es)\s+([A-Za-zÁÉÍÓÚÑáéíóúñ]+)/i.exec(m.contenido)?.[1])
        .filter(Boolean)
        .at(-1);
      return dicho
        ? `Te llamas ${dicho}. ¡Lo recuerdo porque está en el historial que me enviaron!`
        : "No lo sé: no está en el historial que recibí.";
    }
    if (/\bhola\b|buenas/i.test(ultimo)) return "¡Hola! Soy un LLM simulado (mock). Cambia LLM_PROVIDER en .env para hablar con uno real.";
    return `(mock) Recibí ${msgs.length} mensaje(s). Tu último mensaje fue: "${ultimo.slice(0, 80)}"`;
  }
}

🆕 Nuevosrc/llm/medido.ts

Por qué: Un contador de llamadas, tokens y tiempo, con tope de seguridad. Si un agente se descontrola, el tope lo detiene antes de gastar tu cuota.

  • Patrón Decorator: recibe un LLMProvider y TAMBIÉN es un LLMProvider. Por eso se puede poner sobre cualquier proveedor.
  • estimarTokens: ≈ 4 caracteres por token. No es exacto, pero basta para vigilar costos.
  • maxLlamadas: lanza «Presupuesto agotado» al pasarse. Es nuestro primer límite de administración.
  • El finally mide el tiempo incluso cuando la llamada falla.
Código
import type { LLMProvider, Mensaje, OpcionesChat } from "./types.js";

/** Estimación rápida: ~4 caracteres ≈ 1 token (suficiente para controlar costos en clase). */
export const estimarTokens = (t: string) => Math.ceil(t.length / 4);

/**
 * Patrón DECORATOR: envuelve cualquier proveedor y le agrega métricas
 * (llamadas, tokens estimados, tiempo) sin modificar el proveedor original.
 * Esto es "administrar" agentes: lo que no se mide, no se controla.
 */
export class LLMMedido implements LLMProvider {
  llamadas = 0;
  tokensEntrada = 0;
  tokensSalida = 0;
  msTotal = 0;
  errores = 0;

  constructor(
    private readonly interno: LLMProvider,
    /** Tope de llamadas: protege tu cuota y tu bolsillo de un agente descontrolado. */
    private readonly maxLlamadas = Infinity,
  ) {}

  get nombre() {
    return this.interno.nombre;
  }

  async chat(mensajes: Mensaje[], op?: OpcionesChat): Promise<string> {
    if (this.llamadas >= this.maxLlamadas) {
      throw new Error(`Presupuesto agotado: máximo ${this.maxLlamadas} llamadas al LLM`);
    }
    this.llamadas++;
    this.tokensEntrada += estimarTokens(mensajes.map((m) => m.contenido).join(""));
    const t0 = Date.now();
    try {
      const r = await this.interno.chat(mensajes, op);
      this.tokensSalida += estimarTokens(r);
      return r;
    } catch (e) {
      this.errores++;
      throw e;
    } finally {
      this.msTotal += Date.now() - t0;
    }
  }

  resumen(): string {
    return `📊 ${this.llamadas} llamadas · ~${this.tokensEntrada} tokens in / ~${this.tokensSalida} out · ${this.msTotal} ms · ${this.errores} errores`;
  }
}

🆕 Nuevosrc/util/http.ts

Por qué: Un único lugar para hacer POST con JSON, con timeout y reintentos. Los tres proveedores lo reutilizan.

  • Reintenta SOLO 429 y errores 5xx; un 401/403/404 falla de inmediato (reintentar no lo arregla).
  • AbortSignal.timeout: una llamada colgada no bloquea tu agente para siempre.
  • Espera exponencial: 800 ms, 1,6 s… para no martillar a un servicio ya saturado.
Código
import { ErrorLLM } from "../llm/types.js";

/**
 * POST JSON con reintentos simples.
 * Reintenta solo cuando tiene sentido: 429 (límite de uso) y errores 5xx.
 * Es una de las "buenas prácticas de producción" que veremos en clase.
 */
export async function postJson(
  proveedor: string,
  url: string,
  headers: Record<string, string>,
  cuerpo: unknown,
  { reintentos = 2, timeoutMs = 30_000 } = {},
): Promise<any> {
  let ultimoError: ErrorLLM | undefined;

  for (let intento = 0; intento <= reintentos; intento++) {
    try {
      const resp = await fetch(url, {
        method: "POST",
        headers: { "Content-Type": "application/json", ...headers },
        body: JSON.stringify(cuerpo),
        signal: AbortSignal.timeout(timeoutMs),
      });

      if (resp.ok) return await resp.json();

      const detalle = (await resp.text()).slice(0, 300);
      ultimoError = new ErrorLLM(proveedor, `HTTP ${resp.status}: ${detalle}`, resp.status);

      const reintentable = resp.status === 429 || resp.status >= 500;
      if (!reintentable) throw ultimoError;
    } catch (e) {
      if (e instanceof ErrorLLM && !(e.status === 429 || (e.status ?? 0) >= 500)) throw e;
      ultimoError =
        e instanceof ErrorLLM ? e : new ErrorLLM(proveedor, `Fallo de red: ${(e as Error).message}`);
    }

    if (intento < reintentos) await dormir(800 * 2 ** intento); // espera exponencial
  }
  throw ultimoError!;
}

export const dormir = (ms: number) => new Promise((r) => setTimeout(r, ms));
🆕 Nuevosrc/llm/providers/gemini.ts

Por qué: Adaptador de Google Gemini. Traduce nuestro formato al de Gemini.

  • Gemini separa el system (campo systemInstruction) del resto de mensajes.
  • Llama «model» al asistente: traducimos assistant → model.
  • La clave va en un header (x-goog-api-key), nunca en la URL: las URLs quedan en logs.
  • La respuesta viene en candidates[0].content.parts: aquí se extrae el texto.
Código
import { ErrorLLM, type LLMProvider, type Mensaje, type OpcionesChat } from "../types.js";
import { postJson } from "../../util/http.js";

/** Estrategia #1 — Google Gemini (API REST, sin SDK). */
export class GeminiProvider implements LLMProvider {
  readonly nombre: string;

  constructor(
    private readonly apiKey: string,
    private readonly modelo = process.env.GEMINI_MODEL ?? "gemini-2.5-flash",
  ) {
    this.nombre = `gemini:${modelo}`;
  }

  async chat(mensajes: Mensaje[], op: OpcionesChat = {}): Promise<string> {
    // Gemini separa el "system" del resto y llama "model" al asistente.
    const system = mensajes.filter((m) => m.rol === "system").map((m) => m.contenido).join("\n\n");
    const contents = mensajes
      .filter((m) => m.rol !== "system")
      .map((m) => ({
        role: m.rol === "assistant" ? "model" : "user",
        parts: [{ text: m.contenido }],
      }));

    const cuerpo = {
      ...(system && { systemInstruction: { parts: [{ text: system }] } }),
      contents,
      generationConfig: {
        temperature: op.temperatura ?? 0.3,
        maxOutputTokens: op.maxTokens ?? 1024,
        ...(op.json && { responseMimeType: "application/json" }),
      },
    };

    const data = await postJson(
      this.nombre,
      `https://generativelanguage.googleapis.com/v1beta/models/${this.modelo}:generateContent`,
      { "x-goog-api-key": this.apiKey },
      cuerpo,
    );

    const texto = data?.candidates?.[0]?.content?.parts?.map((p: any) => p.text ?? "").join("");
    if (!texto) throw new ErrorLLM(this.nombre, "Respuesta vacía o bloqueada por filtros de seguridad");
    return texto;
  }
}

Paso 4 · Resiliencia: Fallback y comparar proveedores

Crear una estrategia compuesta que prueba varios proveedores en orden y comparar la misma pregunta entre todos.

❓ Qué problema resuelve

Los proveedores fallan: se acaba la cuota (429), hay caídas (503) o van lentos. Si tu agente depende de uno solo, tu sistema se cae con él. La solución es una estrategia COMPUESTA: prueba varios en orden y, como también implementa LLMProvider, el agente ni se entera.

🧠 Conceptos clave

Composite / Fallback
Una estrategia que contiene otras estrategias y las prueba en cadena.
Bitácora
Registro de a quién se le pidió y qué pasó. Imprescindible para entender por qué una respuesta vino de donde vino.
Fallos simulados
El mock ahora puede fallar a propósito para practicar la resiliencia sin esperar a que un proveedor real se caiga.

Por qué: Recibe una lista de proveedores y le pide a cada uno en orden hasta que uno responda. Si todos fallan, lanza un error que explica cada falla.

Código
import { ErrorLLM, type LLMProvider, type Mensaje, type OpcionesChat } from "../types.js";

/**
 * Estrategia COMPUESTA — prueba varios proveedores en orden.
 * Si el primero falla (límite de cuota, caída, timeout…), pasa al siguiente.
 * Observa: ¡también implementa LLMProvider! El agente no nota la diferencia.
 */
export class FallbackProvider implements LLMProvider {
  readonly nombre: string;
  /** Registro de a quién se le pidió y qué pasó (para mostrar en clase). */
  readonly bitacora: string[] = [];

  constructor(private readonly cadena: LLMProvider[]) {
    if (!cadena.length) throw new Error("FallbackProvider necesita al menos un proveedor");
    this.nombre = `fallback[${cadena.map((p) => p.nombre).join(" → ")}]`;
  }

  async chat(mensajes: Mensaje[], op?: OpcionesChat): Promise<string> {
    const errores: string[] = [];
    for (const proveedor of this.cadena) {
      try {
        const respuesta = await proveedor.chat(mensajes, op);
        this.bitacora.push(`✅ ${proveedor.nombre}`);
        return respuesta;
      } catch (e) {
        const msg = (e as Error).message;
        this.bitacora.push(`❌ ${proveedor.nombre} — ${msg.slice(0, 80)}`);
        errores.push(msg);
      }
    }
    throw new ErrorLLM(this.nombre, `Todos los proveedores fallaron:\n  - ${errores.join("\n  - ")}`);
  }
}

      return dicho

❓ Qué problema resuelve

Una conversación real necesita contexto: el modelo no recuerda nada, así que debes reenviarle el historial. Pero reenviar todo cuesta cada vez más y se acerca al límite de tokens; reenviar poco hace que olvide. Decidir cuánto recordar es una decisión INTERCAMBIABLE: otra vez Strategy.

🧠 Conceptos clave

System prompt
Instrucciones permanentes: rol, reglas y formato. Se envía en cada llamada.
Memoria como Strategy
Completa (todo), Ventana (últimos N) y Resumen (lo viejo se comprime con el propio LLM).
Equilibrio costo ↔ olvido
Más memoria = más tokens y más costo. Menos memoria = el bot «olvida».

🆕 Nuevosrc/agentes/memoria.ts

Por qué: Define la interfaz EstrategiaMemoria y tres implementaciones. Es el segundo patrón Strategy del proyecto.

  • MemoriaCompleta guarda todo: simple, pero crece sin límite.
  • MemoriaVentana(n) descarta lo antiguo: costo constante pero olvida (¡se verá en la demo!).
  • MemoriaResumen usa el propio LLM para resumir lo viejo: equilibrio, a cambio de una llamada extra.
Código
import type { LLMProvider, Mensaje } from "../llm/types.js";

/**
 * SEGUNDO PATRÓN STRATEGY de la clase: la MEMORIA.
 * Un LLM no recuerda nada entre llamadas: tú le reenvías el historial.
 * ¿Cuánto historial reenviar? Esa decisión es intercambiable → Strategy.
 */
export interface EstrategiaMemoria {
  readonly nombre: string;
  agregar(m: Mensaje): Promise<void> | void;
  /** Mensajes que se enviarán al LLM (sin el system prompt). */
  obtener(): Mensaje[];
  limpiar(): void;
}

/** Guarda TODO. Simple, pero crece sin límite (más tokens = más caro y más lento). */
export class MemoriaCompleta implements EstrategiaMemoria {
  readonly nombre = "completa";
  protected historial: Mensaje[] = [];
  agregar(m: Mensaje) { this.historial.push(m); }
  obtener() { return [...this.historial]; }
  limpiar() { this.historial = []; }
}

/** Solo recuerda los últimos N mensajes (ventana deslizante). Barata, pero olvida lo antiguo. */
export class MemoriaVentana implements EstrategiaMemoria {
  readonly nombre: string;
  private historial: Mensaje[] = [];
  constructor(private readonly maxMensajes = 6) {
    this.nombre = `ventana(${maxMensajes})`;
  }
  agregar(m: Mensaje) {
    this.historial.push(m);
    if (this.historial.length > this.maxMensajes) this.historial = this.historial.slice(-this.maxMensajes);
  }
  obtener() { return [...this.historial]; }
  limpiar() { this.historial = []; }
}

/** Cuando el historial se alarga, le pide al propio LLM que lo resuma. Equilibrio calidad/costo. */
export class MemoriaResumen implements EstrategiaMemoria {
  readonly nombre = "resumen";
  private resumen = "";
  private reciente: Mensaje[] = [];

  constructor(private readonly llm: LLMProvider, private readonly mantener = 4) {}

  async agregar(m: Mensaje) {
    this.reciente.push(m);
    if (this.reciente.length > this.mantener * 2) {
      const viejos = this.reciente.splice(0, this.reciente.length - this.mantener);
      const texto = viejos.map((x) => `${x.rol}: ${x.contenido}`).join("\n");
      this.resumen = await this.llm.chat([
        { rol: "system", contenido: "Eres un resumidor. Resume la conversación conservando nombres, datos y decisiones. Máximo 80 palabras." },
        { rol: "user", contenido: `Resumen previo: ${this.resumen || "(ninguno)"}\n\nNueva conversación:\n${texto}` },
      ]);
    }
  }

  obtener(): Mensaje[] {
    const base: Mensaje[] = this.resumen
      ? [{ rol: "user", contenido: `[Resumen de la conversación anterior]: ${this.resumen}` }, { rol: "assistant", contenido: "Entendido, tengo ese contexto." }]
      : [];
    return [...base, ...this.reciente];
  }
  limpiar() { this.resumen = ""; this.reciente = []; }
}

Por qué: Nuestro primer agente: junta un LLM, un system prompt y una memoria. Todavía no decide acciones, pero ya tiene personalidad y contexto.

  • Recibe un LLMProvider y una EstrategiaMemoria: dos Strategy combinadas.

Código
import type { LLMProvider } from "../llm/types.js";
import { MemoriaCompleta, type EstrategiaMemoria } from "./memoria.js";

/**
 * NIVEL 1 — Chatbot con rol y memoria.
 * Todavía NO es un agente (no decide acciones), pero ya tiene:
 *   • un system prompt (personalidad / reglas)
 *   • memoria (historial reenviado en cada turno)
 */
export class ChatAgent {
  constructor(
    private readonly llm: LLMProvider,
    private readonly systemPrompt: string,
    private readonly memoria: EstrategiaMemoria = new MemoriaCompleta(),
  ) {}

  async responder(texto: string): Promise<string> {
    await this.memoria.agregar({ rol: "user", contenido: texto });

    const respuesta = await this.llm.chat([
      { rol: "system", contenido: this.systemPrompt },
      ...this.memoria.obtener(),
    ]);

    await this.memoria.agregar({ rol: "assistant", contenido: respuesta });
    return respuesta;
  }

  /** ¿Cuántos mensajes se están reenviando? Útil para ver cómo crece el costo. */
  get mensajesEnMemoria() {
    return this.memoria.obtener().length;
  }
}

import { dormir } from "../../util/http.js";

interface OpcionesMock {
  /** Simula una caída del proveedor (para practicar el fallback). */
  fallar?: boolean;
  /** Latencia artificial en milisegundos. */
  latenciaMs?: number;
  /** Nombre visible (útil cuando creas varios mocks). */
  etiqueta?: string;
}

/**
 * Estrategia #4 — Mock: un "LLM falso" que funciona SIN internet y SIN claves.
 * No es inteligente: usa reglas simples y reconoce el protocolo de nuestros agentes.
 * Sirve para: practicar sin gastar cuota, hacer pruebas y entender el flujo.
 */
export class MockProvider implements LLMProvider {
  readonly nombre: string;
  constructor(private readonly op: OpcionesMock = {}) {
    this.nombre = op.etiqueta ?? "mock";
  }

  async chat(mensajes: Mensaje[]): Promise<string> {
    if (this.op.fallar) throw new ErrorLLM(this.nombre, "Fallo simulado (503 servicio no disponible)", 503);
    if (this.op.latenciaMs) await dormir(this.op.latenciaMs);

    const system = mensajes.filter((m) => m.rol === "system").map((m) => m.contenido).join(" ").toLowerCase();
    const resto = mensajes.filter((m) => m.rol !== "system");

    if (system.includes("resumidor")) return `Resumen (mock): ${resto.map((m) => m.contenido).join(" ").slice(0, 140)}…`;
    return this.conversar(resto);
  }

  // ---------- Conversación normal (niveles 0 y 1) ----------
  private conversar(msgs: Mensaje[]): string {
    const ultimo = msgs.filter((m) => m.rol === "user").at(-1)?.contenido ?? "";
    if (/c[oó]mo me llamo|cu[aá]l es mi nombre/i.test(ultimo)) {
      const dicho = msgs
        .map((m) => /(?:me llamo|mi nombre es)\s+([A-Za-zÁÉÍÓÚÑáéíóúñ]+)/i.exec(m.contenido)?.[1])
        .filter(Boolean)
        .at(-1);
      return dicho
        ? `Te llamas ${dicho}. ¡Lo recuerdo porque está en el historial que me enviaron!`
        : "No lo sé: no está en el historial que recibí.";
    }
    if (/\bhola\b|buenas/i.test(ultimo)) return "¡Hola! Soy un LLM simulado (mock). Cambia LLM_PROVIDER en .env para hablar con uno real.";
    return `(mock) Recibí ${msgs.length} mensaje(s). Tu último mensaje fue: "${ultimo.slice(0, 80)}"`;
  }
}

🆕 Nuevosrc/tools/herramienta.ts

Por qué: El contrato de una herramienta y la caja que las agrupa.

  • Herramienta: nombre, descripcion, ejemploEntrada y ejecutar(). Así de simple.
  • describir() genera el texto que se pegará en el system prompt: una línea por herramienta.
  • ejecutar() captura los errores y los devuelve como TEXTO: una herramienta que falla jamás debe tumbar al agente (el agente puede leer el error y corregirse).
Código
/**
 * Una HERRAMIENTA es una función normal de TypeScript + una descripción en texto.
 * La descripción es lo que el LLM "lee" para decidir cuándo usarla.
 * (¡La descripción es tan importante como el código!)
 */
export interface Herramienta {
  /** Identificador sin espacios: el LLM escribirá este nombre para invocarla. */
  nombre: string;
  /** Qué hace y cuándo usarla. Sé claro y breve. */
  descripcion: string;
  /** Ejemplo del valor de "entrada" (ayuda a los modelos pequeños). */
  ejemploEntrada: string;
  ejecutar(entrada: string): Promise<string> | string;
}

/** Caja de herramientas de un agente. */
export class CajaDeHerramientas {
  private readonly mapa = new Map<string, Herramienta>();

  constructor(herramientas: Herramienta[] = []) {
    herramientas.forEach((h) => this.agregar(h));
  }

  agregar(h: Herramienta): this {
    this.mapa.set(h.nombre, h);
    return this;
  }

  tiene(nombre: string) {
    return this.mapa.has(nombre);
  }

  nombres() {
    return [...this.mapa.keys()];
  }

  /** Texto que se pega en el system prompt para que el LLM conozca las herramientas. */
  describir(): string {
    if (!this.mapa.size) return "(sin herramientas)";
    return [...this.mapa.values()]
      .map((h) => `- ${h.nombre}: ${h.descripcion} Ejemplo de entrada: "${h.ejemploEntrada}"`)
      .join("\n");
  }

  /** Ejecuta con red de seguridad: un error de la herramienta NUNCA debe tumbar al agente. */
  async ejecutar(nombre: string, entrada: string): Promise<string> {
    const h = this.mapa.get(nombre);
    if (!h) return `Error: la herramienta "${nombre}" no existe. Herramientas válidas: ${this.nombres().join(", ")}`;
    try {
      return String(await h.ejecutar(entrada));
    } catch (e) {
      return `Error al ejecutar "${nombre}": ${(e as Error).message}`;
    }
  }
}
🆕 Nuevosrc/tools/calculadora.ts

Por qué: Un LLM se equivoca sumando. Esta herramienta calcula con exactitud, y lo hace SIN eval() (que permitiría ejecutar código malicioso).

  • Un parser propio por descenso recursivo: solo entiende números, + - * / % ^ y paréntesis.
  • Rechaza cualquier otro carácter con un error claro: process.exit() no pasa.
  • La descripción le dice al LLM «úsala SIEMPRE que haya cuentas».
Código
import type { Herramienta } from "./herramienta.js";

/**
 * Evaluador matemático SEGURO (descenso recursivo).
 * ⚠️ NUNCA uses eval() con texto que viene de un LLM: es una puerta abierta
 * para ejecutar código malicioso (inyección de prompts). Este parser solo
 * entiende números, + - * / % ^ y paréntesis.
 *
 * Gramática:  expr  := term (('+'|'-') term)*
 *             term  := pot  (('*'|'/'|'%') pot)*
 *             pot   := unario ('^' pot)?
 *             unario:= '-' unario | '(' expr ')' | número
 */
export function evaluar(texto: string): number {
  const s = texto.replace(/\s+/g, "").replace(/,/g, ".");
  if (!/^[\d+\-*/%^().]+$/.test(s)) throw new Error(`Caracteres no permitidos en "${texto}"`);
  let i = 0;

  const peek = () => s[i];
  const expr = (): number => {
    let v = term();
    while (peek() === "+" || peek() === "-") v = s[i++] === "+" ? v + term() : v - term();
    return v;
  };
  const term = (): number => {
    let v = pot();
    while (peek() === "*" || peek() === "/" || peek() === "%") {
      const op = s[i++];
      const d = pot();
      if ((op === "/" || op === "%") && d === 0) throw new Error("División por cero");
      v = op === "*" ? v * d : op === "/" ? v / d : v % d;
    }
    return v;
  };
  const pot = (): number => {
    const base = unario();
    if (peek() === "^") {
      i++;
      return base ** pot();
    }
    return base;
  };
  const unario = (): number => {
    if (peek() === "-") {
      i++;
      return -unario();
    }
    if (peek() === "(") {
      i++;
      const v = expr();
      if (s[i++] !== ")") throw new Error("Falta cerrar paréntesis");
      return v;
    }
    const m = /^\d+(\.\d+)?/.exec(s.slice(i));
    if (!m) throw new Error(`Se esperaba un número en la posición ${i}`);
    i += m[0].length;
    return parseFloat(m[0]);
  };

  const resultado = expr();
  if (i < s.length) throw new Error(`Sobra texto desde la posición ${i}: "${s.slice(i)}"`);
  return resultado;
}

export const calculadora: Herramienta = {
  nombre: "calculadora",
  descripcion: "Resuelve operaciones matemáticas (+ - * / % ^ y paréntesis). Úsala SIEMPRE que haya cuentas; los LLM se equivocan sumando.",
  ejemploEntrada: "(12 + 8) * 3",
  ejecutar: (entrada) => {
    const r = evaluar(entrada);
    return `${entrada.trim()} = ${Number.isInteger(r) ? r : r.toFixed(4).replace(/0+$/, "")}`;
  },
};

🆕 Nuevosrc/util/json.ts

Por qué: Los LLM a veces envuelven el JSON en ``json … `` o añaden texto. Este «limpiador» encuentra el objeto JSON dentro.

  • Quita las vallas de código y recorta entre la primera { y la última }.
  • Si no hay JSON lanza un error: el agente lo manejará.
Código
/**
 * Los LLM a veces envuelven el JSON en ```json ... ``` o añaden texto extra.
 * Esta función es el "limpiador": encuentra el primer objeto JSON válido.
 */
export function extraerJson<T = any>(texto: string): T {
  const limpio = texto.replace(/```(?:json)?/gi, "").trim();
  const ini = limpio.indexOf("{");
  const fin = limpio.lastIndexOf("}");
  if (ini === -1 || fin <= ini) throw new Error("No encontré un objeto JSON en la respuesta");
  return JSON.parse(limpio.slice(ini, fin + 1)) as T;
}

Por qué: Define el protocolo: el texto que se pone en el system prompt y la función que interpreta la respuesta del LLM.

Código
import type { CajaDeHerramientas } from "../tools/herramienta.js";
import { extraerJson } from "../util/json.js";

/**
 * EL PROTOCOLO: cómo "hablamos" con el LLM para que use herramientas.
 * Le pedimos que responda SIEMPRE en JSON con uno de dos formatos.
 * Ventaja: funciona igual en Gemini, Cohere y Groq (sin depender del
 * "function calling" nativo de cada proveedor, que cambia entre ellos).
 */
export type DecisionLLM =
  | { tipo: "accion"; pensamiento: string; accion: string; entrada: string }
  | { tipo: "final"; pensamiento: string; respuesta: string };

export function promptProtocolo(rol: string, herramientas: CajaDeHerramientas, extra = ""): string {
  return `${rol}

HERRAMIENTAS DISPONIBLES:
${herramientas.describir()}

Responde SIEMPRE con UN solo objeto JSON válido, sin texto adicional. Hay dos formatos:

1) Cuando necesites una herramienta:
{"pensamiento": "por qué la necesito", "accion": "nombre_de_la_herramienta", "entrada": "texto de entrada"}

2) Cuando ya tengas la información para responder:
{"pensamiento": "por qué ya puedo responder", "respuesta_final": "respuesta clara para el usuario"}

REGLAS:
- Usa UNA herramienta por turno. Después recibirás un mensaje que empieza con "Observación:".
- No inventes datos: si no los tienes, usa una herramienta o dilo con honestidad.
- Si una herramienta devuelve un error, corrige la entrada o intenta otra forma.
- Responde en español.${extra ? "\n" + extra : ""}`;
}

/** Convierte el texto del LLM en una decisión tipada (o lanza error si el formato es inválido). */
export function interpretar(texto: string): DecisionLLM {
  const j = extraerJson<Record<string, unknown>>(texto);
  const pensamiento = typeof j.pensamiento === "string" ? j.pensamiento : "";

  if (typeof j.respuesta_final === "string") return { tipo: "final", pensamiento, respuesta: j.respuesta_final };
  if (typeof j.accion === "string") {
    return { tipo: "accion", pensamiento, accion: j.accion, entrada: j.entrada == null ? "" : String(j.entrada) };
  }
  throw new Error('El JSON no tiene ni "accion" ni "respuesta_final"');
}

🆕 Nuevosrc/agentes/ToolAgent.ts

Por qué: El Nivel 2: pregunta → el LLM decide → se ejecuta UNA herramienta → el LLM redacta la respuesta.

  • Dos llamadas al LLM: una para decidir y otra para redactar con la observación.
  • La herramienta la ejecuta NUESTRO código (herramientas.ejecutar), no el LLM.
  • Si el LLM pide una segunda herramienta, responde que este nivel solo usa una: ese es su límite, y el gancho para el Nivel 3.
Código
import type { LLMProvider, Mensaje } from "../llm/types.js";
import type { CajaDeHerramientas } from "../tools/herramienta.js";
import { interpretar, promptProtocolo } from "./protocolo.js";
import type { Escucha } from "./eventos.js";

/**
 * NIVEL 2 — Agente con herramientas (UNA sola vez).
 *   Pregunta → el LLM decide → se ejecuta UNA herramienta → el LLM redacta.
 * Es un agente "de un solo disparo": sirve para tareas simples,
 * pero falla si la pregunta necesita encadenar varias herramientas.
 */
export class ToolAgent {
  constructor(
    private readonly llm: LLMProvider,
    private readonly herramientas: CajaDeHerramientas,
    private readonly escucha: Escucha = () => {},
    private readonly nombre = "ToolAgent",
  ) {}

  async ejecutar(pregunta: string): Promise<string> {
    const system = promptProtocolo(
      "Eres un asistente útil.",
      this.herramientas,
      "- Solo puedes usar UNA herramienta en total para esta pregunta.",
    );
    const mensajes: Mensaje[] = [
      { rol: "system", contenido: system },
      { rol: "user", contenido: pregunta },
    ];

    // Llamada 1: ¿necesita herramienta?
    const crudo = await this.llm.chat(mensajes, { json: true, temperatura: 0 });
    const decision = interpretar(crudo);
    this.escucha({ agente: this.nombre, tipo: "pensamiento", paso: 1, texto: decision.pensamiento });

    if (decision.tipo === "final") return decision.respuesta;

    // Ejecutamos la herramienta (código normal, NO el LLM).
    this.escucha({ agente: this.nombre, tipo: "accion", paso: 1, texto: `${decision.accion}("${decision.entrada}")` });
    const observacion = await this.herramientas.ejecutar(decision.accion, decision.entrada);
    this.escucha({ agente: this.nombre, tipo: "observacion", paso: 1, texto: observacion });

    // Llamada 2: el LLM redacta la respuesta usando la observación.
    mensajes.push({ rol: "assistant", contenido: crudo }, { rol: "user", contenido: `Observación: ${observacion}` });
    const segunda = interpretar(await this.llm.chat(mensajes, { json: true, temperatura: 0 }));

    if (segunda.tipo === "final") return segunda.respuesta;
    // Quiso usar otra herramienta, pero este nivel no lo permite → límite del Nivel 2.
    return `(Nivel 2 solo usa una herramienta) Esto es lo que obtuve: ${observacion}`;
  }
}

        : "No lo sé: no está en el historial que recibí.";
    }
    if (/\bhola\b|buenas/i.test(ultimo)) return "¡Hola! Soy un LLM simulado (mock). Cambia LLM_PROVIDER en .env para hablar con uno real.";

  private reaccionar(msgs: Mensaje[], system: string): string {
    // Solo la tarea: ignoramos el bloque de contexto de pasos anteriores.
    const pregunta = (msgs.find((m) => m.rol === "user")?.contenido ?? "").split("\n\n[Contexto")[0] ?? "";
    const observaciones = msgs
      .filter((m) => m.rol === "user" && m.contenido.startsWith("Observación:"))
      .map((m) => m.contenido.replace("Observación:", "").trim());

    // Solo considera las herramientas que el agente realmente tiene disponibles.
    const pendientes = this.herramientasNecesarias(pregunta).filter((h) => system.includes(`- ${h.nombre}:`));
    const siguiente = pendientes[observaciones.length];

    if (siguiente) {
      return JSON.stringify({
        pensamiento: `Necesito usar "${siguiente.nombre}" para avanzar.`,
        accion: siguiente.nombre,
        entrada: siguiente.entrada,
      });
    }
    const respuesta = observaciones.length
      ? `Con lo que obtuve: ${observaciones.join(" | ")}`
      : `No necesito herramientas para esto. (mock) Pregunta: ${pregunta.slice(0, 80)}`;
    return JSON.stringify({ pensamiento: "Ya tengo lo necesario para responder.", respuesta_final: respuesta });
  }

  private herramientasNecesarias(texto: string) {
    const hallazgos: { pos: number; nombre: string; entrada: string }[] = [];
    const clima = /clima|temperatura|llueve/i.exec(texto);
    if (clima) {
      hallazgos.push({ pos: clima.index, nombre: "clima", entrada: /\ben ([A-ZÁÉÍÓÚÑ][\wáéíóúñ]+)/.exec(texto)?.[1] ?? "Bogotá" });
    }
    // Expresión matemática: números, operadores y paréntesis (debe contener al menos un operador).
    const mat = [...texto.matchAll(/\(*\d[\d\s+\-*/^%().]*[\d)]/g)].find((m) => /[+\-*/^%]/.test(m[0]));
    if (mat) hallazgos.push({ pos: mat.index ?? 0, nombre: "calculadora", entrada: mat[0].trim() });
    const hora = /\bhora\b/i.exec(texto);
    if (hora) hallazgos.push({ pos: hora.index, nombre: "hora", entrada: "" });
    const def = /qu[eé] (?:es|son) (?:un |una |el |la |los |las )?(.+?)(?:\s+y\s|[?.,;]|$)/i.exec(texto);
    if (def) hallazgos.push({ pos: def.index, nombre: "buscar_conocimiento", entrada: def[1]!.trim() });
    return hallazgos.sort((a, b) => a.pos - b.pos);
  }

❓ Qué problema resuelve

El Nivel 2 se rinde si la tarea necesita varias herramientas. Un agente de verdad repite: piensa qué falta, actúa con una herramienta, observa el resultado y vuelve a pensar, hasta tener la respuesta. Pero un bucle puede salir mal (JSON roto, repetir lo mismo, no terminar nunca), así que el bucle trae defensas.

🧠 Conceptos clave

ReAct (Reason + Act)
El patrón: Pensar → Actuar → Observar, en bucle, hasta responder.
Defensa 1: formato
Si el JSON es inválido, se le pide al LLM que corrija en vez de abortar.
Defensa 2: acciones repetidas
Una «huella» de cada acción detecta que el agente se quedó dando vueltas.
Defensa 3: maxPasos
Freno de emergencia: ningún agente se ejecuta para siempre ni gasta sin límite.

Por qué: El corazón del curso: el bucle del agente. El LLM es el cerebro que decide; NUESTRO código es el cuerpo que ejecuta, valida y corta.

  • for (paso = 1; paso <= maxPasos…): el bucle, con tope.
  • Defensa 1: try { interpretar } — si falla, añade un mensaje de corrección y continue.
  • Defensa 2: accionesHechas guarda «accion::entrada»; repetirla devuelve una observación que le dice al LLM que cambie de enfoque.
  • Los errores de herramientas vuelven como observación: el agente puede corregirse (ej.: ciudad desconocida).
  • Devuelve ResultadoAgente con pasos, si se cortó por límite y todos los eventos.

import type { LLMProvider, Mensaje } from "../llm/types.js";
import type { CajaDeHerramientas } from "../tools/herramienta.js";
import { interpretar, promptProtocolo } from "./protocolo.js";
import type { Escucha, EventoAgente } from "./eventos.js";

export interface ResultadoAgente {
  respuesta: string;
  /** Cuántas vueltas del bucle se usaron. */
  pasos: number;
  /** true si se cortó por llegar al máximo de pasos (no por terminar bien). */
  cortadoPorLimite: boolean;
  eventos: EventoAgente[];
}

export interface OpcionesReAct {
  llm: LLMProvider;
  herramientas: CajaDeHerramientas;
  /** Personalidad y misión del agente (va al system prompt). */
  rol: string;
  nombre?: string;
  /** Freno de emergencia contra bucles infinitos. */
  maxPasos?: number;
  escucha?: Escucha;
}

/**
 * NIVEL 3 — Agente ReAct (Reason + Act).
 *
 *     ┌──────────────────────────────────────────┐
 *     │  1. PENSAR   ¿qué necesito saber/hacer?  │
 *     │  2. ACTUAR   llamar una herramienta      │
 *     │  3. OBSERVAR leer el resultado           │
 *     └───────── repetir hasta tener respuesta ──┘
 *
 * El LLM es el "cerebro" que decide; NUESTRO CÓDIGO es el "cuerpo" que ejecuta.
 */
export class ReActAgent {
  readonly nombre: string;
  private readonly maxPasos: number;

  constructor(private readonly op: OpcionesReAct) {
    this.nombre = op.nombre ?? "ReAct";
    this.maxPasos = op.maxPasos ?? 6;
  }

  async ejecutar(tarea: string, contexto = ""): Promise<ResultadoAgente> {
    const eventos: EventoAgente[] = [];
    const emitir = (paso: number, tipo: EventoAgente["tipo"], texto: string) => {
      const e = { agente: this.nombre, tipo, paso, texto };
      eventos.push(e);
      this.op.escucha?.(e);
    };

    const mensajes: Mensaje[] = [
      { rol: "system", contenido: promptProtocolo(this.op.rol, this.op.herramientas) },
      { rol: "user", contenido: contexto ? `${tarea}\n\n[Contexto de pasos anteriores]\n${contexto}` : tarea },
    ];
    const accionesHechas = new Set<string>();

    for (let paso = 1; paso <= this.maxPasos; paso++) {
      const crudo = await this.op.llm.chat(mensajes, { json: true, temperatura: 0 });

      // --- Defensa 1: el LLM no respondió con el formato esperado ---
      let decision;
      try {
        decision = interpretar(crudo);
      } catch (e) {
        emitir(paso, "error", `Formato inválido (${(e as Error).message}). Se le pide corregir.`);
        mensajes.push(
          { rol: "assistant", contenido: crudo },
          { rol: "user", contenido: 'Error de formato: responde SOLO con un objeto JSON con "accion" o "respuesta_final".' },
        );
        continue;
      }

      emitir(paso, "pensamiento", decision.pensamiento);

      if (decision.tipo === "final") {
        emitir(paso, "final", decision.respuesta);
        return { respuesta: decision.respuesta, pasos: paso, cortadoPorLimite: false, eventos };
      }

      // --- Defensa 2: detectar que el agente repite lo mismo (bucle) ---
      const huella = `${decision.accion}::${decision.entrada}`;
      let observacion: string;
      if (accionesHechas.has(huella)) {
        observacion = "Ya ejecutaste exactamente esa acción. No la repitas: usa lo que ya sabes o cambia de enfoque.";
        emitir(paso, "error", `Acción repetida: ${huella}`);
      } else {
        accionesHechas.add(huella);
        emitir(paso, "accion", `${decision.accion}("${decision.entrada}")`);
        observacion = await this.op.herramientas.ejecutar(decision.accion, decision.entrada);
        emitir(paso, "observacion", observacion);
      }

      mensajes.push({ rol: "assistant", contenido: crudo }, { rol: "user", contenido: `Observación: ${observacion}` });
    }

    // --- Defensa 3: freno de emergencia ---
    const aviso = `No pude terminar en ${this.maxPasos} pasos. Última información: ${mensajes.at(-1)?.contenido ?? ""}`;
    emitir(this.maxPasos, "error", "Límite de pasos alcanzado");
    return { respuesta: aviso, pasos: this.maxPasos, cortadoPorLimite: true, eventos };
  }
}

❓ Qué problema resuelve

Una herramienta le dice al agente QUÉ puede hacer. Pero ¿cómo le enseñas A HACERLO BIEN (formatos, reglas de tu empresa, pasos)? Meter todas las instrucciones en el prompt lo llena y lo encarece. 🧠 Conceptos clave

Tool vs Skill
Tool = función que el agente ejecuta (hacer). Skill = instrucciones que el agente lee (saber cómo).
SKILL.md
Una carpeta con un SKILL.md: encabezado con name y description, y el cuerpo con las instrucciones.
Divulgación progresiva
Siempre se ve el catálogo (nombre + descripción); el cuerpo completo se carga solo si la tarea lo requiere.
Skill entregada por una tool
En este proyecto la skill llega al agente mediante la herramienta cargar_skill.

/**
 * SKILLS ≠ TOOLS
 *   • Tool  = una FUNCIÓN que el agente puede ejecutar (acción: calcular, consultar el clima…).
 *   • Skill = un PAQUETE DE INSTRUCCIONES (un SKILL.md) que le enseña CÓMO hacer una tarea.
 *
 * Una skill es una carpeta:   skills/<nombre>/SKILL.md
 *   ---
 *   name: reporte-clima
 *   description: qué hace y cuándo usarla      ← esto es lo ÚNICO que el agente ve siempre
 *   ---
 *   (instrucciones completas…)                 ← esto se carga SOLO cuando hace falta
 *
 * Esa carga "por demanda" se llama DIVULGACIÓN PROGRESIVA: 50 skills instaladas no llenan
 * el contexto, porque el agente solo lleva el catálogo (nombre + descripción) y pide el resto.
 * Aquí lo implementamos "desde cero": la carga se entrega al agente mediante una herramienta.
 */
export interface Skill {
  nombre: string;
  descripcion: string;
  instrucciones: string;
}

/** Separa el encabezado YAML simple (clave: valor) del cuerpo en Markdown. */
export function parsearSkill(texto: string, nombreCarpeta: string): Skill {
  const m = /^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$/.exec(texto.trim());
  if (!m) throw new Error(`La skill "${nombreCarpeta}" no tiene encabezado --- ... ---`);

  const meta: Record<string, string> = {};
  for (const linea of m[1]!.split(/\r?\n/)) {
    const kv = /^([A-Za-z_-]+):\s*(.*)$/.exec(linea);
    if (kv) meta[kv[1]!.toLowerCase()] = kv[2]!.trim();
  }
  const nombre = meta.name ?? nombreCarpeta;
  if (!meta.description) throw new Error(`La skill "${nombre}" necesita "description" (el agente decide con ella cuándo usarla)`);
  return { nombre, descripcion: meta.description, instrucciones: m[2]!.trim() };
}

  /** Nivel 2: las instrucciones completas, bajo demanda. */
  cargar(nombre: string): string {
    const s = this.skills.get(nombre.trim());
    if (!s) throw new Error(`No existe la skill "${nombre}". Skills válidas: ${this.nombres().join(", ") || "(ninguna)"}`);
    return `Instrucciones de la skill "${s.nombre}":\n${s.instrucciones}`;
  }

  /** La skill llega al agente a través de una HERRAMIENTA de carga. */
  comoHerramienta(): Herramienta {
    return {
      nombre: "cargar_skill",
      descripcion:

        `Skills disponibles: ${this.nombres().join(", ")}. La entrada es SOLO el nombre exacto de la skill.`,

/** Une los resultados parciales en una respuesta final (usado por Nivel 4 y Nivel 5). */
export async function sintetizar(
  llm: LLMProvider,
  tarea: string,
  resultados: { paso: string; respuesta: string }[],
): Promise<string> {
  const datos = resultados.map((r, i) => `${i + 1}. ${r.paso} → ${r.respuesta}`).join("\n");
  return llm.chat([
    {
      rol: "system",
      contenido:

        "Usa SOLO los datos entregados; no inventes nada.",
    },
    { rol: "user", contenido: `Tarea original: ${tarea}\n\nResultados:\n${datos}` },
  ]);
}

/**
 * NIVEL 4 — Plan-and-Execute (planificar y luego ejecutar).
 *
 *   1) PLANIFICAR : un LLM divide la tarea en pasos.
 *   2) EJECUTAR   : un agente ReAct resuelve cada paso (con el contexto de los anteriores).
 *   3) SINTETIZAR : otro LLM une todo en una respuesta final.
 *
 * Ventaja sobre ReAct puro: en tareas largas el agente no se "pierde", porque
 * tiene un mapa (el plan) y puedes mostrarlo / aprobarlo antes de ejecutar.
 */
export class PlanificadorAgent {
  constructor(
    private readonly llm: LLMProvider,
    private readonly ejecutor: ReActAgent,
    private readonly escucha: Escucha = () => {},
    private readonly maxPasosPlan = 6,
  ) {}

  async planear(tarea: string): Promise<string[]> {
    const crudo = await this.llm.chat(
      [
        {
          rol: "system",
          contenido:
            "Eres un PLANIFICADOR. Divide la tarea del usuario en pasos cortos, concretos y en orden. " +
            `Máximo ${this.maxPasosPlan} pasos. Responde SOLO con JSON: {"pensamiento": "...", "pasos": ["paso 1", "paso 2"]}`,
        },
        { rol: "user", contenido: tarea },
      ],
      { json: true, temperatura: 0 },
    );
    const pasos = extraerJson<{ pasos?: unknown }>(crudo).pasos;
    if (!Array.isArray(pasos) || !pasos.length) throw new Error("El planificador no devolvió pasos");
    return pasos.map(String).slice(0, this.maxPasosPlan);
  }

  async ejecutar(tarea: string): Promise<ResultadoPlan> {
    const plan = await this.planear(tarea);
    this.escucha({ agente: "Planificador", tipo: "plan", paso: 0, texto: plan.map((p, i) => `${i + 1}) ${p}`).join("  ") });

    const resultados: ResultadoPlan["resultados"] = [];
    for (const [i, paso] of plan.entries()) {
      this.escucha({ agente: "Planificador", tipo: "delegacion", paso: i + 1, texto: `Ejecutando: ${paso}` });
      const contexto = resultados.map((r) => `- ${r.paso}: ${r.respuesta}`).join("\n");
      const r = await this.ejecutor.ejecutar(paso, contexto);
      resultados.push({ paso, respuesta: r.respuesta });
    }

    const respuesta = await sintetizar(this.llm, tarea, resultados);
    this.escucha({ agente: "Planificador", tipo: "final", paso: plan.length + 1, texto: respuesta });
    return { plan, resultados, respuesta };
  }
}

import { ErrorLLM, type LLMProvider, type Mensaje } from "../types.js";
import { dormir } from "../../util/http.js";

interface OpcionesMock {
  /** Simula una caída del proveedor (para practicar el fallback). */
  fallar?: boolean;
  /** Latencia artificial en milisegundos. */
  latenciaMs?: number;
  /** Nombre visible (útil cuando creas varios mocks). */
  etiqueta?: string;
}

/**
 * Estrategia #4 — Mock: un "LLM falso" que funciona SIN internet y SIN claves.
 * No es inteligente: usa reglas simples y reconoce el protocolo de nuestros agentes.
 * Sirve para: practicar sin gastar cuota, hacer pruebas y entender el flujo.
 */
export class MockProvider implements LLMProvider {
  readonly nombre: string;
  constructor(private readonly op: OpcionesMock = {}) {
    this.nombre = op.etiqueta ?? "mock";
  }

  async chat(mensajes: Mensaje[]): Promise<string> {
    if (this.op.fallar) throw new ErrorLLM(this.nombre, "Fallo simulado (503 servicio no disponible)", 503);
    if (this.op.latenciaMs) await dormir(this.op.latenciaMs);

    const system = mensajes.filter((m) => m.rol === "system").map((m) => m.contenido).join(" ").toLowerCase();
    const resto = mensajes.filter((m) => m.rol !== "system");

    if (system.includes("planificador")) return this.planificar(resto);
    if (system.includes("resumidor")) return `Resumen (mock): ${resto.map((m) => m.contenido).join(" ").slice(0, 140)}…`;
    if (system.includes('"accion"')) return this.reaccionar(resto, system);
    return this.conversar(resto);
  }

  // ---------- Conversación normal (niveles 0 y 1) ----------
  private conversar(msgs: Mensaje[]): string {
    const ultimo = msgs.filter((m) => m.rol === "user").at(-1)?.contenido ?? "";
    if (/c[oó]mo me llamo|cu[aá]l es mi nombre/i.test(ultimo)) {
      const dicho = msgs
        .map((m) => /(?:me llamo|mi nombre es)\s+([A-Za-zÁÉÍÓÚÑáéíóúñ]+)/i.exec(m.contenido)?.[1])
        .filter(Boolean)
        .at(-1);
      return dicho
        ? `Te llamas ${dicho}. ¡Lo recuerdo porque está en el historial que me enviaron!`
        : "No lo sé: no está en el historial que recibí.";
    }
    if (/\bhola\b|buenas/i.test(ultimo)) return "¡Hola! Soy un LLM simulado (mock). Cambia LLM_PROVIDER en .env para hablar con uno real.";
    return `(mock) Recibí ${msgs.length} mensaje(s). Tu último mensaje fue: "${ultimo.slice(0, 80)}"`;
  }

  // ---------- Protocolo de herramientas (niveles 2, 3 y especialistas) ----------
  private reaccionar(msgs: Mensaje[], system: string): string {
    // Solo la tarea: ignoramos el bloque de contexto de pasos anteriores.
    const pregunta = (msgs.find((m) => m.rol === "user")?.contenido ?? "").split("\n\n[Contexto")[0] ?? "";
    const observaciones = msgs
      .filter((m) => m.rol === "user" && m.contenido.startsWith("Observación:"))
      .map((m) => m.contenido.replace("Observación:", "").trim());

    // Solo considera las herramientas que el agente realmente tiene disponibles.
    const pendientes = this.herramientasNecesarias(pregunta).filter((h) => system.includes(`- ${h.nombre}:`));
    const siguiente = pendientes[observaciones.length];

    if (siguiente) {
      return JSON.stringify({
        pensamiento: `Necesito usar "${siguiente.nombre}" para avanzar.`,
        accion: siguiente.nombre,
        entrada: siguiente.entrada,
      });
    }
    // Las observaciones que son instrucciones de una skill no son "datos": se usan como guía.
    const PREFIJO_SKILL = "Instrucciones de la skill";
    const skill = /^Instrucciones de la skill "([^"]+)"/.exec(observaciones.find((o) => o.startsWith(PREFIJO_SKILL)) ?? "")?.[1];
    const datos = observaciones.filter((o) => !o.startsWith(PREFIJO_SKILL));
    const respuesta = observaciones.length
      ? `${skill ? `Siguiendo la skill "${skill}": ` : "Con lo que obtuve: "}${datos.join(" | ")}`
      : `No necesito herramientas para esto. (mock) Pregunta: ${pregunta.slice(0, 80)}`;
    return JSON.stringify({ pensamiento: "Ya tengo lo necesario para responder.", respuesta_final: respuesta });
  }

  private herramientasNecesarias(texto: string) {
    const hallazgos: { pos: number; nombre: string; entrada: string }[] = [];
    const clima = /clima|temperatura|llueve/i.exec(texto);
    if (clima) {
      hallazgos.push({ pos: clima.index, nombre: "clima", entrada: /\ben ([A-ZÁÉÍÓÚÑ][\wáéíóúñ]+)/.exec(texto)?.[1] ?? "Bogotá" });
    }

    const mat = [...texto.matchAll(/\(*\d[\d\s+\-*/^%().]*[\d)]/g)].find((m) => /[+\-*/^%]/.test(m[0]));
    if (mat) hallazgos.push({ pos: mat.index ?? 0, nombre: "calculadora", entrada: mat[0].trim() });
    // Si piden un "reporte/informe", el mock carga la skill adecuada ANTES de actuar.
    const rep = /\b(reporte|informe)\b/i.exec(texto);
    if (rep) {
      hallazgos.push({ pos: rep.index, nombre: "cargar_skill", entrada: /clima|temperatura/i.test(texto) ? "reporte-clima" : "resumen-ejecutivo" });
    }
    const hora = /\bhora\b/i.exec(texto);
    if (hora) hallazgos.push({ pos: hora.index, nombre: "hora", entrada: "" });
    const def = /qu[eé] (?:es|son) (?:un |una |el |la |los |las )?(.+?)(?:\s+y\s|[?.,;]|$)/i.exec(texto);
    if (def) hallazgos.push({ pos: def.index, nombre: "buscar_conocimiento", entrada: def[1]!.trim() });
    return hallazgos.sort((a, b) => a.pos - b.pos);
  }

  // ---------- Nivel 4: planificador ----------
  private planificar(msgs: Mensaje[]): string {
    const tarea = msgs.filter((m) => m.rol === "user").at(-1)?.contenido ?? "";
    const pasos = tarea
      .split(/\s+y\s+|,\s*|;\s*|\s+luego\s+|\s+despu[eé]s\s+/i)
      .map((p) => p.replace(/^[¿¡\s]+|[?!.\s]+$/g, ""))
      .filter((p) => p.length > 3);
    return JSON.stringify({ pensamiento: "Divido la tarea en pasos pequeños.", pasos: pasos.length ? pasos : [tarea] });
  }
}

❓ Qué problema resuelve

Un solo agente con muchas herramientas se confunde, es caro y es difícil de probar. Varios agentes pequeños, cada uno con pocas herramientas y un rol claro, son más precisos, más seguros (mínimo privilegio) y se pueden medir y reemplazar por separado.

🧠 Conceptos clave

Orquestador
El «jefe»: decide a quién delegar cada subtarea y une los resultados.
Mínimo privilegio
Cada especialista ve SOLO las herramientas que necesita.
Administración
Registrar agentes, medir ejecuciones, éxitos, fallos y tiempos (el tablero).

Por qué: Registra especialistas, delega, sintetiza y mide. Es a la vez el «jefe» y el «administrador» del equipo.

  • Especialista: nombre, descripción (para que el orquestador decida) y un ReActAgent propio.

import type { LLMProvider } from "../llm/types.js";
import { extraerJson } from "../util/json.js";
import type { Escucha } from "./eventos.js";
import { sintetizar } from "./PlanificadorAgent.js";
import type { ReActAgent } from "./ReActAgent.js";

/** Un especialista: un agente + una descripción para que el orquestador sepa cuándo usarlo. */
export interface Especialista {
  nombre: string;
  descripcion: string;
  agente: ReActAgent;
}

export interface Estadistica {
  ejecuciones: number;
  exitos: number;
  fallos: number;
  msTotal: number;
}

/**
 * NIVEL 5 — Sistema multi-agente con ORQUESTADOR.
 *
 *            ┌────────────── Orquestador ──────────────┐
 *            │  decide a QUIÉN delegar cada subtarea   │
 *            └───────┬──────────────┬──────────────────┘
 *              Investigador     Matemático   … (cada uno con SUS herramientas)
 *
 * Por qué varios agentes pequeños y no uno gigante:
 *   • cada uno tiene pocas herramientas → se confunde menos
 *   • prompts cortos y enfocados → más baratos y más precisos
 *   • puedes probar, medir y reemplazar cada especialista por separado
 *
 * Esta clase también es el ADMINISTRADOR: registra, ejecuta y mide a los agentes.
 */
export class Orquestador {
  private readonly especialistas = new Map<string, Especialista>();
  readonly estadisticas = new Map<string, Estadistica>();

  constructor(
    private readonly llm: LLMProvider,
    especialistas: Especialista[],
    private readonly escucha: Escucha = () => {},
  ) {
    especialistas.forEach((e) => this.registrar(e));
  }

  registrar(e: Especialista) {
    this.especialistas.set(e.nombre, e);
    this.estadisticas.set(e.nombre, { ejecuciones: 0, exitos: 0, fallos: 0, msTotal: 0 });
  }

  quitar(nombre: string) {
    this.especialistas.delete(nombre);
  }

  listar() {
    return [...this.especialistas.values()].map((e) => ({ nombre: e.nombre, descripcion: e.descripcion }));
  }

  private async delegar(d: { agente: string; tarea: string }): Promise<string> {
    const esp = this.especialistas.get(d.agente);
    if (!esp) return `Error: no existe el especialista "${d.agente}". Disponibles: ${[...this.especialistas.keys()].join(", ")}`;

    const est = this.estadisticas.get(d.agente)!;
    const t0 = Date.now();
    est.ejecuciones++;
    try {
      const r = await esp.agente.ejecutar(d.tarea);
      if (r.cortadoPorLimite) est.fallos++;
      else est.exitos++;
      return r.respuesta;
    } catch (e) {
      est.fallos++;
      return `Error del especialista: ${(e as Error).message}`;
    } finally {
      est.msTotal += Date.now() - t0;
    }
  }

  async ejecutar(tarea: string): Promise<{ respuesta: string; delegaciones: { agente: string; tarea: string; respuesta: string }[] }> {
    const catalogo = this.listar().map((e) => `- ${e.nombre}: ${e.descripcion}`).join("\n");
    const crudo = await this.llm.chat(
      [
        {
          rol: "system",
          contenido:
            `Eres un ORQUESTADOR. Reparte la tarea entre estos especialistas:\n${catalogo}\n\n` +
            'Responde SOLO con JSON: {"pensamiento": "...", "delegaciones": [{"agente": "nombre_exacto", "tarea": "subtarea clara y autocontenida"}]}',
        },
        { rol: "user", contenido: tarea },
      ],
      { json: true, temperatura: 0 },
    );

    const delegaciones: { agente: string; tarea: string; respuesta: string }[] = [];
    for (const [i, d] of lista.entries()) {
      this.escucha({ agente: "Orquestador", tipo: "delegacion", paso: i + 1, texto: `→ ${d.agente}: ${d.tarea}` });
      delegaciones.push({ ...d, respuesta: await this.delegar(d) });
    }

    const respuesta = await sintetizar(
      this.llm,
      tarea,
      delegaciones.map((d) => ({ paso: `${d.agente}: ${d.tarea}`, respuesta: d.respuesta })),
    );
    this.escucha({ agente: "Orquestador", tipo: "final", paso: lista.length + 1, texto: respuesta });
    return { respuesta, delegaciones };
  }

  /** Tablero de administración: ¿quién trabaja bien y quién falla? */
  tablero(): string {
    const filas = [...this.estadisticas.entries()].map(
      ([n, s]) => `  ${n.padEnd(14)} ejecuciones=${s.ejecuciones}  ok=${s.exitos}  fallos=${s.fallos}  tiempo=${s.msTotal}ms`,
    );
    return ["📋 Tablero de agentes:", ...filas].join("\n");
  }

/**
 * SOLUCIÓN del reto "Convertidor de moneda".
 * Tasas FIJAS de ejemplo (no son valores reales de mercado).
 * Observa cómo la descripción le explica al LLM el formato exacto de la entrada.
 */
import type { Herramienta } from "../tools/herramienta.js";

const COP_POR_UNIDAD: Record<string, number> = { COP: 1, USD: 4000, EUR: 4400, MXN: 230 };

export const convertirMoneda: Herramienta = {
  nombre: "convertir_moneda",
  descripcion:
    "Convierte dinero entre COP, USD, EUR y MXN con tasas de ejemplo. " +
    'La entrada debe tener el formato "monto MONEDA_ORIGEN a MONEDA_DESTINO".',
  ejemploEntrada: "50 USD a COP",
  ejecutar: (entrada) => {
    const m = /^\s*([\d.,]+)\s*([A-Za-z]{3})\s+a\s+([A-Za-z]{3})\s*$/i.exec(entrada);
    if (!m) throw new Error('Formato inválido. Usa: "50 USD a COP"');

    const monto = parseFloat(m[1]!.replace(",", "."));
    const origen = m[2]!.toUpperCase();
    const destino = m[3]!.toUpperCase();
    const tOrigen = COP_POR_UNIDAD[origen];
    const tDestino = COP_POR_UNIDAD[destino];
    if (!tOrigen || !tDestino) throw new Error(`Monedas soportadas: ${Object.keys(COP_POR_UNIDAD).join(", ")}`);

    const resultado = (monto * tOrigen) / tDestino;
    return `${monto} ${origen} = ${resultado.toLocaleString("es-CO", { maximumFractionDigits: 2 })} ${destino} (tasa de ejemplo)`;
  },
};
🆕 Nuevosrc/soluciones/ollama.ts

Por qué: Una nueva estrategia LLM: un modelo local. Es la prueba de que Strategy funciona: una clase nueva, cero cambios en agentes.

  • Casi idéntica a groq.ts: solo cambian URL, no requiere clave y el timeout es mayor.
  • Para activarla, agrega un case "ollama" en factory.ts.
Código
/**
 * SOLUCIÓN del reto "Nueva estrategia": un LLM LOCAL con Ollama (https://ollama.com).
 * Ollama expone una API compatible con OpenAI en http://localhost:11434/v1, así que el código
 * es casi idéntico al de Groq. ¡Esa es la gracia de Strategy: una clase nueva, cero cambios en los agentes!
 *
 * Cómo usarla: instala Ollama, ejecuta `ollama pull llama3.2` y en factory.ts añade:
 *     case "ollama": return new OllamaProvider();
 */
import { ErrorLLM, type LLMProvider, type Mensaje, type OpcionesChat } from "../llm/types.js";
import { postJson } from "../util/http.js";

export class OllamaProvider implements LLMProvider {
  readonly nombre: string;

  constructor(
    private readonly modelo = process.env.OLLAMA_MODEL ?? "llama3.2",
    private readonly baseUrl = process.env.OLLAMA_URL ?? "http://localhost:11434/v1",
  ) {
    this.nombre = `ollama:${modelo}`;
  }

  async chat(mensajes: Mensaje[], op: OpcionesChat = {}): Promise<string> {
    const data = await postJson(
      this.nombre,
      `${this.baseUrl}/chat/completions`,
      {}, // local: no necesita clave
      {
        model: this.modelo,
        messages: mensajes.map((m) => ({ role: m.rol, content: m.contenido })),
        temperature: op.temperatura ?? 0.3,
        max_tokens: op.maxTokens ?? 1024,
        ...(op.json && { response_format: { type: "json_object" } }),
      },
      { timeoutMs: 120_000 }, // los modelos locales pueden tardar más
    );

    const texto = data?.choices?.[0]?.message?.content;
    if (!texto) throw new ErrorLLM(this.nombre, "Respuesta vacía");
    return texto;
  }
}
