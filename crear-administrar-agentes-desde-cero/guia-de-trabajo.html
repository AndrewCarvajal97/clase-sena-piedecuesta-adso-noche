4. Guion del instructor por bloque

Bloque 1 · Vocabulario (40 min)

Mensaje central: un LLM es una función sin memoria que predice texto; un agente es código que lo usa en un bucle con herramientas.
  • Analogía del autocompletar: el teclado del celular sugiere la siguiente palabra; un LLM hace lo mismo pero entrenado con casi todo internet.
  • Demo de "sin memoria": en la diapositiva 10 pregunta al grupo "¿cómo se acuerda ChatGPT de lo que dije?" → Respuesta: la aplicación reenvía el historial.
  • Pregunta clave (diap. 13): "¿El camino lo conozco de antemano?" Si sí, no necesitas agente.
  • Cierra con la Actividad 1 (10 min). Quien termine el reto de parejas con 0 errores explica un término.
Error comúnPensar que "el LLM ejecuta la herramienta". No: solo pide que se ejecute; tu código decide si lo hace.

Bloque 2 · Niveles y Strategy (50 min)

Mensaje central: el agente no debe saber si habla con Gemini, Cohere o Groq. Eso se logra con una interfaz común.
  1. Muestra la escalera de niveles (diap. 19–20) como mapa de lo que construirán.
  2. Dolor primero: diap. 21 (el if por proveedor). Pregunta: "¿qué pasa cuando Groq cambie su API?".
  3. Explica Strategy con las 3 analogías (GPS, enchufe, pagos) y luego el diagrama (diap. 23).
  4. Live coding: abre llm/types.ts, luego providers/groq.ts, luego factory.ts. Muestra que Gemini cambia assistant→model y separa system.
  5. Ejecuta npm run nivel0. Que cada aprendiz cambie LLM_PROVIDER y repita (¡cero cambios de código!).
  6. npm run comparar: misma pregunta, distintos proveedores y demo de Fallback.
  7. Actividad 2 (15 min): Strategy Playground con el reto de "2 caídas seguidas".
Dato para explicar DecoratorLLMMedido envuelve a cualquier proveedor sin modificarlo. Como también cumple LLMProvider, se pueden apilar: Medido(Fallback([Groq, Gemini])).

Bloque 3 · Memoria y herramientas (40 min)

  • Nivel 1: npm run nivel1 -- ventana --demo. Observa que al final no recuerda el nombre. Luego repite con completa y compara.
  • Nivel 2: abre tools/basicas.ts. Resalta que la descripción es lo único que el LLM lee.
  • Seguridad: abre tools/calculadora.ts y explica por qué no se usa eval(). Prueba evaluar("process.exit()").
  • Protocolo JSON: abre agentes/protocolo.ts. Explica por qué es portable entre proveedores.
  • npm run nivel2: la tercera pregunta necesita 2 herramientas y el nivel 2 no puede → gancho para el bucle.

Bloque 4 · ReAct (50 min)

Mensaje central: el LLM es el cerebro que decide; tu código es el cuerpo que ejecuta, valida y corta.
  1. Dibuja en el tablero el ciclo Pensar → Actuar → Observar.
  2. Abre agentes/ReActAgent.ts y señala las 3 defensas: formato inválido, acción repetida, límite de pasos.
  3. npm run nivel3 y lee la traza en voz alta, paso a paso.
  4. Experimento guiado: cambia maxPasos a 1; luego pregunta algo que necesite una herramienta inexistente.
  5. Actividad 3 (20 min): simulador ReAct. Pide que provoquen un bucle y expliquen qué defensa lo detuvo.
Para discutirCon el mock el agente "siempre acierta". Con un LLM real puede equivocarse. ¿Qué defensas del código ayudan? ¿Cuáles no alcanzan?

Bloque 5 · Planificar, orquestar y administrar (35 min)

  • Nivel 4: npm run nivel4. Resalta que el plan se imprime antes de ejecutar (podrías pedir aprobación).
  • Nivel 5: npm run nivel5. Muestra el tablero final: ejecuciones, éxitos, fallos y tiempo por agente.
  • Lista de control (diap. 46): límites, observabilidad, seguridad, resiliencia, calidad, humano en el bucle.
  • Regla de oro (diap. 47): el nivel más bajo que resuelva el problema.
  • Actividad 4: pestañas 4 (¿qué nivel?), 5 (Prompt Lab) y 6 (caza-bugs). Repartir por parejas.

E3 · Tu primera herramienta (15 min)

Crea src/tools/miHerramienta.ts con una herramienta convertir_moneda (entrada: "50 USD a COP"). Agrégala en bootstrap.ts a todasLasHerramientas() y ejecuta:

npm run nivel3 -- "¿Cuánto son 50 USD a COP?"
Nota con mockEl mock solo reconoce 4 herramientas (calculadora, clima, hora, buscar_conocimiento). Para ver tu herramienta nueva en acción necesitas un proveedor real (Groq, Gemini o Cohere). Solución: src/soluciones/convertirMoneda.ts.

E4 · Que el agente falle bien (10 min)

  • Pregunta por el clima de una ciudad que no existe. ¿El agente se cae o se recupera?
  • Cambia maxPasos a 1 en nivel3-react.ts con una pregunta de dos herramientas.
  • Crea new LLMMedido(proveedor, 2) y observa el error de presupuesto.

E5 · Un tercer especialista (15 min)

En nivel5-multiagente.ts agrega un especialista traductor o redactor con su propia caja (puede ir vacía) y su descripción. Pregunta: ¿por qué conviene que cada especialista tenga pocas herramientas?

7. Evaluación rápida (10 preguntas)

  1. ¿Un LLM recuerda lo que le dijiste en la llamada anterior? (No; reenviamos el historial.)
  2. ¿Qué es un token y por qué importa? (Trozo de texto; define costo, límites y ventana de contexto.)
  3. ¿Quién ejecuta realmente una herramienta? (Tu código, no el LLM.)
  4. Define agente en una frase. (LLM + herramientas + bucle para cumplir un objetivo.)
  5. ¿Cuáles son los pasos de ReAct? (Pensar, actuar, observar; repetir.)
  6. ¿Qué problema resuelve Strategy aquí? (Cambiar de proveedor sin tocar los agentes.)
  7. ¿Para qué sirve FallbackProvider? (Pasar al siguiente proveedor si uno falla.)
  8. ¿Por qué nunca eval() con texto del LLM? (Es entrada no confiable; riesgo de ejecución arbitraria.)
  9. Nombra 3 defensas del bucle ReAct. (JSON inválido, acción repetida, límite de pasos.)
  10. ¿Cuándo NO usar un agente? (Cuando el camino es conocido: un flujo fijo es más barato y predecible.)

8. Solución de problemas

SíntomaCausa probableQué hacer
Falta GROQ_API_KEY en tu archivo .envNo copiaste .env.example o falta la claveCopia el archivo, pega la clave, o usa LLM_PROVIDER=mock.
HTTP 401 / 403Clave incorrecta, vencida o con espaciosGenera otra clave y pégala sin comillas ni espacios.
HTTP 429Cuota gratuita agotadaEspera un minuto, baja la frecuencia o usa LLM_PROVIDER=fallback.
"Formato inválido" en la trazaEl modelo no devolvió JSON limpioEs normal de vez en cuando: el agente pide corregir. Si es constante, usa un modelo más grande o baja la temperatura.
process.loadEnvFile is not a functionNode anterior a 20.12Actualiza Node (recomendado 22 LTS).
El agente repite la misma acciónEl modelo no entendió la observaciónMejora la descripción de la herramienta o el mensaje de error que devuelve.
Error de modelo no encontrado (404)El proveedor renombró el modeloDefine GEMINI_MODEL, COHERE_MODEL o GROQ_MODEL en .env con uno vigente de su consola.
Modelos y cuotas cambianLos nombres de modelos y los límites gratuitos varían con el tiempo. Los valores por defecto del proyecto están en cada archivo de llm/providers/ y se sobrescriben desde .env sin tocar el código (gracias a Strategy).
