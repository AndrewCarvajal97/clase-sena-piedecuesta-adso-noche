1. Qué vamos a construir y por qué así

Vamos a construir un chat en React que responde preguntas usando nuestros propios documentos (apuntes, reglamento, manual de un producto…). Esta técnica se llama RAG (Retrieval-Augmented Generation): en lugar de confiar en lo que el modelo "recuerda", le entregamos la información justo antes de responder, así contesta con datos reales y alucina mucho menos.

La arquitectura

React (navegador)  ──pregunta──▶  Backend Express (Node)
                   ◀─respuesta──        │
                                        ├─▶ Cohere      (crea embeddings)
                                        ├─▶ Supabase    (busca vectores parecidos)
                                        └─▶ Gemini      (genera la respuesta)

El stack tecnológico

PiezaHerramientaPara qué sirve
FrontendReact + ViteLa interfaz de chat en el navegador
BackendNode.js + ExpressProteger las claves y orquestar el RAG
EmbeddingsCohere embed-multilingual-v3.0 (1024 dimensiones)Convertir texto en vectores
Base vectorialSupabase + extensión pgvectorGuardar y buscar los vectores

Alternativas de base vectorialSi no quieres usar Supabase, puedes usar Pinecone o Upstash Vector (en la nube) o Chroma (local, en tu propio PC). La idea de "guardar embeddings y buscar los más parecidos" es la misma.

2. Por qué se necesita un backend (seguridad de claves)

El código de React se descarga completo al navegador del usuario. Cualquiera puede abrir las herramientas de desarrollo (tecla F12) y leerlo. Por eso, si pusieras una clave de API en el frontend, la estarías publicando: otras personas podrían usarla a tu nombre y agotar tu cupo.

Regla que no se rompeLas claves de API solo viven en el .env del backend. En Vite, además, cualquier variable que empiece por VITE_ es pública: nunca pongas secretos ahí.

Por eso el navegador nunca habla directo con Cohere, Supabase ni Gemini: siempre pasa por nuestro backend, que es el único que conoce las claves.

3. Repaso corto: RAG y base de datos vectorial

Un embedding es una lista de números que captura el significado de un texto (Clase 2). Textos parecidos tienen vectores parecidos. Una base de datos vectorial guarda esos vectores y sabe encontrar "los más parecidos" a uno dado, usando la similitud coseno.

RAG usa esto en tres pasos:

  1. Vectorizar los documentos una vez (ingesta).
  2. Buscar (retrieval) los fragmentos más parecidos a la pregunta.
  3. Generar (generation) la respuesta con el LLM usando SOLO esos fragmentos.

5. Crear el backend con Express

El backend es un servidor pequeño de Node.js con dos endpoints: /ingest (cargar documentos) y /chat (responder preguntas). En una carpeta backend/ aparte:

cd backend

npm install express cors dotenv cohere-ai @google/generative-ai @supabase/supabase-js

Para poder usar import (módulos ES), añade esta línea en el backend/package.json:

{
  "type": "module",
  "scripts": { "start": "node server.js" }

5.1 El archivo server.js

Define el servidor, activa CORS (para que React pueda llamarlo) y crea los dos endpoints. Archivo completo en codigo/backend/server.js:

import express from "express";
import cors from "cors";
import "dotenv/config";                       // carga el .env
import { ingestarTexto, responderPregunta } from "./rag.js";

const app = express();
app.use(cors());                              // permite las llamadas de React
app.use(express.json());                      // permite leer JSON del body

// Endpoint para CARGAR documentos a la base vectorial
app.post("/ingest", async (req, res) => {
  try {
    const { texto } = req.body;
    const n = await ingestarTexto(texto);
    res.json({ ok: true, fragmentos: n });
  } catch (e) {
    res.status(500).json({ error: e.message });
  }
});

// Endpoint para PREGUNTAR al agente RAG
app.post("/chat", async (req, res) => {
  try {
    const { pregunta } = req.body;
    const respuesta = await responderPregunta(pregunta);
    res.json({ respuesta });
  } catch (e) {
    res.status(500).json({ error: e.message });
  }
});

app.listen(3000, () => console.log("Backend escuchando en http://localhost:3000"));
¿Qué es CORS?Por seguridad, el navegador bloquea que una página (localhost:5173) llame a otro origen (localhost:3000). La librería cors le da permiso explícito a nuestro frontend.

6. Configurar Supabase + pgvector

Supabase es una base de datos PostgreSQL en la nube con plan gratuito. Pasos:

  1. Entra a supabase.com, crea una cuenta y un proyecto nuevo (guarda la contraseña de la base).
  2. En el menú lateral abre el SQL Editor.
  3. Pega y ejecuta el contenido de codigo/backend/supabase.sql (lo vemos abajo).
  4. Ve a Project Settings → API y copia la Project URL y la clave service_role.

El SQL habilita pgvector, crea la tabla y la función de búsqueda:

-- 1. Habilitar la extensión de vectores
create extension if not exists vector;

-- 2. Tabla de documentos. 1024 = dimensión de embed-multilingual-v3.0
create table documentos (
  id        bigserial primary key,
  contenido text,
  embedding vector(1024)
);

-- 3. Función que busca los documentos más parecidos (similitud coseno)
create or replace function match_documents(
  query_embedding vector(1024),
  match_count int default 3
)
returns table (id bigint, contenido text, similitud float)
language sql stable
as $$
  select
    id,
    contenido,
    1 - (embedding <=> query_embedding) as similitud
  from documentos
  order by embedding <=> query_embedding   -- <=> es distancia coseno
  limit match_count;
$$;
Clave service_roleEs una clave muy poderosa (puede leer y escribir todo). Úsala solo en el backend, nunca en React. Va en el .env del backend.

7. Ingesta de datos (cargar los documentos)

La ingesta convierte nuestros documentos en vectores y los guarda. Se hace una sola vez (o cada vez que agregas material nuevo). Tres pasos: partir en chunks → generar embeddings → guardar en Supabase.

En codigo/backend/rag.js (parte de ingesta):

import { CohereClient } from "cohere-ai";
import { createClient } from "@supabase/supabase-js";

const cohere = new CohereClient({ token: process.env.COHERE_API_KEY });
const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_KEY);

// Parte un texto largo en fragmentos de ~500 caracteres
function partirEnChunks(texto, tam = 500) {
  const chunks = [];
  for (let i = 0; i < texto.length; i += tam) {
    chunks.push(texto.slice(i, i + tam));
  }
  return chunks;
}

export async function ingestarTexto(texto) {
  const chunks = partirEnChunks(texto);

  // input_type "search_document": textos que se GUARDAN en la base
  const r = await cohere.embed({
    texts: chunks,
    model: "embed-multilingual-v3.0",
    inputType: "search_document",
  });

  // Cada fila = un fragmento + su vector
  const filas = chunks.map((c, i) => ({
    contenido: c,
    embedding: r.embeddings[i],
  }));

  await supabase.from("documentos").insert(filas);
  return chunks.length;
}
¿Por qué chunks?Fragmentos pequeños hacen que la búsqueda sea más precisa (traes justo el pedazo relevante) y que el prompt final sea más corto, lo que sale más barato y rápido.

8. Flujo de consulta: el agente RAG

Cuando el usuario pregunta algo, el backend hace cuatro pasos:

  1. Convertir la pregunta en un embedding (con input_type: "search_query").
  2. Llamar a match_documents en Supabase para traer los chunks más parecidos.
  3. Armar un prompt que incluya ese contexto y una instrucción clara.
  4. Pedirle a Gemini la respuesta y devolverla al frontend.

En codigo/backend/rag.js (parte de consulta):

import { GoogleGenerativeAI } from "@google/generative-ai";
const genai = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

export async function responderPregunta(pregunta) {
  // 1. Embedding de la PREGUNTA (search_query)
  const e = await cohere.embed({
    texts: [pregunta],
    model: "embed-multilingual-v3.0",
    inputType: "search_query",
  });

  // 2. RETRIEVAL: buscar los 3 chunks más parecidos en Supabase
  const { data, error } = await supabase.rpc("match_documents", {
    query_embedding: e.embeddings[0],
    match_count: 3,
  });
  if (error) throw error;

  const contexto = data.map((d) => `- ${d.contenido}`).join("\n");

  // 3. Armar el prompt con el contexto recuperado
  const prompt = `Responde usando ÚNICAMENTE esta información.
Si la respuesta no está ahí, di que no tienes ese dato.

Información:
${contexto}

Pregunta: ${pregunta}`;

  // 4. GENERATION: Gemini genera la respuesta
  const model = genai.getGenerativeModel({ model: "gemini-1.5-flash" });
  const out = await model.generateContent(prompt);
  return out.response.text();
}
El agente no inventaComo le pedimos responder SOLO con el contexto, si la información no está en tus documentos, el agente lo dice en vez de inventar. Así se reducen las alucinaciones.

9. Conectar React con el backend (UI de chat)

En frontend/src/App.jsx creamos un chat sencillo con useState y fetch. Archivo completo en codigo/frontend/App.jsx:

import { useState } from "react";
import "./App.css";

const API = "http://localhost:3000";   // dirección del backend

export default function App() {
  const [mensajes, setMensajes] = useState([]);
  const [texto, setTexto] = useState("");
  const [cargando, setCargando] = useState(false);

  async function enviar() {
    if (!texto.trim()) return;
    const pregunta = texto;
    setMensajes((m) => [...m, { rol: "yo", texto: pregunta }]);
    setTexto("");
    setCargando(true);
    try {
      const r = await fetch(`${API}/chat`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ pregunta }),
      });
      const { respuesta } = await r.json();
      setMensajes((m) => [...m, { rol: "bot", texto: respuesta }]);
    } catch (e) {
      setMensajes((m) => [...m, { rol: "bot", texto: "Error: " + e.message }]);
    } finally {
      setCargando(false);
    }
  }

  return (
    <div className="chat">
      <h1>Asistente RAG</h1>
      <div className="mensajes">
        {mensajes.map((m, i) => (
          <div key={i} className={`msg ${m.rol}`}>{m.texto}</div>
        ))}
        {cargando && <div className="msg bot">escribiendo…</div>}
      </div>
      <div className="fila">
        <input
          value={texto}
          onChange={(e) => setTexto(e.target.value)}
          onKeyDown={(e) => e.key === "Enter" && enviar()}
          placeholder="Escribe tu pregunta..."
        />
        <button onClick={enviar}>Enviar</button>
      </div>
    </div>
  );
}
Orden para probar1) Ejecuta el SQL en Supabase. 2) Arranca el backend (npm start). 3) Carga documentos con /ingest (ver README del código). 4) Arranca el frontend (npm run dev) y pregunta.

10. Seguridad, límites y despliegue

10.1 Seguridad de las claves — ¡crítico!

  1. Todas las claves van en backend/.env, NUNCA en React.
  2. Crea un .gitignore para no subir secretos ni dependencias:
# .gitignore
node_modules/
.env
Si una clave se filtraRevócala de inmediato y genera una nueva desde el panel del proveedor (Cohere, Google AI Studio o Supabase).

10.2 Límites y costos

  • Las APIs gratuitas tienen límites de peticiones por minuto y cupos mensuales.
  • Los LLMs cobran o limitan por token: trae solo 3–4 chunks para que el prompt sea corto.
  • Guarda los embeddings una sola vez (no re-vectorices en cada pregunta).
