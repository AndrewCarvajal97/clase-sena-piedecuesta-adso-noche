¿Qué vamos a construir?

💬

Un chat en React que responde preguntas usando nuestros propios documentos (no lo que el modelo "recuerda" de internet). Es un agente RAG de principio a fin.

La arquitectura

┌──────────────┐   pregunta    ┌─────────────────┐
│  React       │ ────────────▶ │  Backend        │
│ (navegador)  │               │  Express (Node) │
│  chat UI     │ ◀──────────── │  guarda claves  │
└──────────────┘   respuesta   └───────┬─────────┘
                                        │
              ┌─────────────────────────┼───────────────────────┐
              ▼                          ▼                       ▼
     ┌───────────────┐      ┌────────────────────┐    ┌────────────────┐
     │ Cohere        │      │ Supabase /pgvector │    │ Gemini         │
     │ (embeddings)  │      │ (buscar similares) │    │ (generar texto)│
     └───────────────┘      └────────────────────┘    └────────────────┘
La regla de oroEl navegador (React) nunca habla directo con Cohere, Supabase ni Gemini. Todo pasa por nuestro backend, que es quien guarda las claves.

¿Por qué se necesita un backend?

El código de React se descarga completo al navegador: cualquiera puede abrir el inspector y leerlo. Si pones una clave ahí, la estás regalando.

❌ NuncaClave de API en React / .env de Vite → visible para todos → te vacían el cupo.
✅ CorrectoClave en el .env del backend (servidor). El navegador solo ve las respuestas.
Regla prácticaToda variable que empiece por VITE_ es pública. Las claves secretas jamás van ahí.

Repaso: RAG y base vectorial

De la Clase 2 y 4: RAG = Retrieval-Augmented Generation. En 3 pasos:

  1. Vectorizar los documentos (embeddings = listas de números que capturan el significado).
  2. Buscar los fragmentos más parecidos a la pregunta (similitud coseno).
  3. Generar la respuesta usando SOLO esos fragmentos.
Base de datos vectorialUna base vectorial guarda esos embeddings y sabe buscar "los más parecidos" muy rápido. Hoy usamos Supabase con pgvector.

2) El backend Express

Un servidor pequeño con dos endpoints:

  • POST /ingest — recibe texto, lo parte en chunks, genera embeddings y los guarda en Supabase.
  • POST /chat — recibe una pregunta y devuelve la respuesta del agente RAG.
cd backend
npm init -y
npm install express cors dotenv cohere-ai \
    @google/generative-ai @supabase/supabase-js
CORSEl navegador bloquea peticiones a otro origen. cors le da permiso a React (localhost:5173) para llamar al backend (localhost:3000).

backend/server.js

import express from "express";
import cors from "cors";
import "dotenv/config";
import { ingestarTexto, responderPregunta } from "./rag.js";

const app = express();
app.use(cors());              // permite que React llame
app.use(express.json());      // lee JSON del body

// Cargar documentos a la base vectorial
app.post("/ingest", async (req, res) => {
  const { texto } = req.body;
  const n = await ingestarTexto(texto);
  res.json({ ok: true, fragmentos: n });
});

// Preguntar al agente RAG
app.post("/chat", async (req, res) => {
  const { pregunta } = req.body;
  const respuesta = await responderPregunta(pregunta);
  res.json({ respuesta });
});

app.listen(3000, () => console.log("Backend en :3000"));

3) Supabase + pgvector

Supabase es una base de datos PostgreSQL en la nube (con plan gratuito). La extensión pgvector le enseña a guardar y comparar vectores.

  1. Crea un proyecto en supabase.com.
  2. Abre el SQL Editor y ejecuta nuestro supabase.sql.
  3. Copia la URL y la service_role key al .env del backend.
La clave service_roleEs muy poderosa: solo se usa en el backend, jamás en React.

supabase.sql

-- 1. Habilitar la extensión de vectores
create extension if not exists vector;

-- 2. Tabla de documentos (1024 = dimensión de Cohere v3.0)
create table documentos (
  id        bigserial primary key,
  contenido text,
  embedding vector(1024)
);

-- 3. Función de búsqueda por similitud (coseno)
create or replace function match_documents(
  query_embedding vector(1024),
  match_count int default 3
)
returns table (id bigint, contenido text, similitud float)
language sql stable as $$
  select id, contenido,
         1 - (embedding <=> query_embedding) as similitud
  from documentos
  order by embedding <=> query_embedding
  limit match_count;
$$;

El operador <=> es "distancia coseno" de pgvector.

4) Ingesta de datos

Cargar nuestros documentos a la base vectorial, una sola vez:

texto largo
   │  1. partir en CHUNKS (fragmentos)
   ▼
["frag 1", "frag 2", "frag 3", ...]
   │  2. Cohere → EMBEDDINGS (1024 números c/u)
   ▼
[[0.12, -0.4, ...], [0.03, 0.9, ...], ...]
   │  3. guardar en Supabase (tabla documentos)
   ▼
   ✅ base de conocimiento lista
¿Por qué chunks?Fragmentos pequeños = búsquedas más precisas y prompts más cortos (más baratos).

Ingesta — el código (rag.js)

// Partir el texto en fragmentos de ~500 caracteres
function partirEnChunks(texto, tam = 500) {
  const chunks = [];
  for (let i = 0; i < texto.length; i += tam)
    chunks.push(texto.slice(i, i + tam));
  return chunks;
}

export async function ingestarTexto(texto) {
  const chunks = partirEnChunks(texto);
  // input_type "search_document" para textos que se guardan
  const r = await cohere.embed({
    texts: chunks, model: "embed-multilingual-v3.0",
    inputType: "search_document",
  });
  const filas = chunks.map((c, i) => ({
    contenido: c, embedding: r.embeddings[i],
  }));
  await supabase.from("documentos").insert(filas);
  return chunks.length;
}

5) El flujo del agente RAG

pregunta del usuario
   │  1. Cohere → embedding de la pregunta
   ▼
[0.44, -0.1, ...]  (input_type: search_query)
   │  2. Supabase match_documents() → chunks parecidos
   ▼
contexto = "frag A + frag B + frag C"
   │  3. armar prompt: "Responde SOLO con esto: {contexto}"
   ▼
Gemini genera la respuesta
   │  4. devolver al frontend
   ▼
💬 respuesta en el chat de React

Consulta — el código (rag.js)

export async function responderPregunta(pregunta) {
  // 1. Embedding de la pregunta
  const e = await cohere.embed({
    texts: [pregunta], model: "embed-multilingual-v3.0",
    inputType: "search_query",
  });
  // 2. Buscar los chunks más parecidos en Supabase
  const { data } = await supabase.rpc("match_documents", {
    query_embedding: e.embeddings[0], match_count: 3,
  });
  const contexto = data.map(d => d.contenido).join("\n");
  // 3. Prompt con el contexto + 4. Gemini genera
  const prompt = `Responde usando SOLO esta información.
Si no está, di que no la tienes.\n\n${contexto}\n\nPregunta: ${pregunta}`;
  const model = genai.getGenerativeModel({ model: "gemini-1.5-flash" });
  const out = await model.generateContent(prompt);
  return out.response.text();
}

Límites, costos y despliegue

Dónde publicar

  • Frontend (React) → Vercel o Netlify.
  • Backend (Express) → Render o Railway.
  • Las claves se configuran como variables de entorno en el panel del servidor.

Límites y costos

  • Las APIs gratuitas tienen cupos por minuto.
  • Los LLMs cobran por token: contexto corto = más barato.
  • Trae solo 3–4 chunks por pregunta.
